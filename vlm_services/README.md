# VLM Services — двенадцать сервисов на одной инфраструктуре

Продуктовые сервисы поверх зрительно-языковых моделей: от карточек
товаров до помощника для слабовидящих. Общее ядро — работа с
изображениями, вызов VLM по схеме и проверка ответа кодом.

Работает **без ключей и без сети**: провайдер по умолчанию — оффлайн-модель
`fake`, поэтому весь набор запускается и тестируется локально.

```bash
make install
make test      # 178 проверок, ~1.5 с
make serve     # интерфейс на http://127.0.0.1:8081
```

## Интерфейс и API

```bash
make serve      # http://127.0.0.1:8081
```

В интерфейсе: каталог, перетаскивание фото, выбор провайдера, параметры
в JSON, отчёт и сырые данные. Ничего не тянется с CDN — работает в
закрытом контуре.

| метод | ручка | зачем |
|---|---|---|
| `GET` | `/api/services` | каталог |
| `GET` | `/api/services/{slug}` | схема ответа и демо-параметры |
| `POST` | `/api/services/{slug}/upload` | файлы формой (multipart) |
| `POST` | `/api/services/{slug}/run` | JSON с data-URI |
| `POST` | `/api/services/{slug}/demo` | прогон на демо-данных |
| `GET` | `/health` | статус для оркестратора |

```bash
curl -X POST localhost:8081/api/services/retail-audit/upload \
     -F files=@shelf.jpg -F 'params={"our_brand":"Аква","min_sos_pct":40}'
```

**Про доступ.** Без `VLM_API_TOKEN` сервис слушает только localhost и
отказывается стартовать на внешнем адресе: открытый эндпоинт с оплатой
за токены находят быстро.

## Принцип: модель смотрит, код считает

VLM хорошо описывает изображение и плохо считает. Поэтому модель
называет то, что видит, а выводы, от которых зависят деньги и
безопасность, вычисляются кодом.

- **Доля полки** (№2) — арифметика по фейсингам, а не «на глаз 30%». Это
  предмет спора между производителем и сетью.
- **Контраст** (№5) — формула WCAG по названным цветам: «кнопка сливается
  с фоном» превращается в «2.06:1 при норме 3.0:1».
- **Калории** (№7) — коэффициенты Этуотера по БЖУ, иначе в дневнике
  копится арифметический шум.
- **Смета** (№4) — нормы расхода и запас на подрезку в коде; ошибка
  модели в умножении стоила бы клиенту лишних поддонов плитки.
- **Суммы в документах** (№9) — сходимость позиций с итогом, НДС и
  контрольные разряды ИНН проверяются без обращения к реестрам.

### Экономия на изображениях

Провайдеры берут плату за пиксели. Фото с телефона 4000×3000 (184 КБ)
ужимается до 1024×768 (4.8 КБ) — **payload в 38 раз меньше** при той же
информативности: деталей мельче 1024 px модель всё равно не различает.
Порог настраивается через `VLM_MAX_SIDE_PX`.

## Где обещания исходной идеи скорректированы

Три формулировки из ТЗ не выдерживают проверки практикой, и сервисы
сделаны иначе. Это осознанные решения, а не недоделки.

**«100% автоматизация ввода данных без человека» (№9).** На рукописной
накладной ошибается и человек. Сервис вместо этого сам проверяет то, что
поддаётся проверке, и маршрутизирует документ: `auto` или
`manual_review`. Получается реальная автоматизация 80–90% потока вместо
обещанных 100%, зато без тихих ошибок в учёте.

**«Замена сотен живых модераторов» (№10).** Контекст решает: один и тот
же кадр бывает пропагандой и историческим документом. Автоматически
проходят только уверенно чистые и уверенно запрещённые случаи, серая
зона и всё неоднозначное идёт человеку. Экономия кратная, но честная —
за ошибочную блокировку площадка отвечает перед пользователем, а за
пропуск запрещённого перед регулятором.

**«Примерная рыночная стоимость» одним числом (№11).** По фотографии
нельзя отличить подлинник от хорошей копии: клеймо и патина
подделываются. Сервис даёт два сценария — «если подлинник» и «если
реплика» — и всегда рекомендует очный осмотр. Ломбард, выдавший деньги
под уверенную оценку копии, получит судебный иск.

Кроме того, №5 возвращает **диапазон** потенциала роста конверсии, а не
точный процент: по одному скриншоту его не предсказать, он зависит от
трафика и оффера.

## Как устроено

```
vlmkit/
  config.py           Settings: провайдер, лимиты на изображения
  images.py           загрузка, проверка, нормализация, data-URI
  vlm.py              фабрика VLM + FakeVLM (оффлайн)
  core.py             Service, Result, реестр, разбор ответов
  demo.py             демо-кадры со сценами
  api.py / cli.py     REST + интерфейс, командная строка
  web/index.html      интерфейс без внешних зависимостей
  services/           двенадцать модулей, каждый регистрирует себя сам
```

Сервис объявляет роль, схему ответа и реализует `analyze()`:

```python
@register
class MyService(Service):
    slug = "my-service"
    system = "Ты эксперт по…"
    schema = {"items": [{"name": "", "count": 0}]}

    def analyze(self, images, threshold: float = 0.5):
        data = self.ask("Что на фото?", images)
        return {"result": ..., "_warnings": [...]}
```

Имена параметров `analyze` — это контракт: опечатка вроде `min_sos_pc`
вместо `min_sos_pct` отвергается с перечнем доступных имён, а не уходит
молча в `**kwargs`, оставляя клиента с ответом по умолчанию.

### Оффлайн-режим

`FakeVLM` не пустышка: она читает описание сцены, приложенное к
демо-кадру, и отвечает по схеме сервиса. Поэтому тесты проверяют логику
(пороги, арифметику, формулировки), а не фантазию модели, и весь набор
гоняется без ключей. Реальному провайдеру описание сцены не уходит —
это проверено отдельным тестом.

## Провайдеры

```bash
export VLM_PROVIDER=openai VLM_API_KEY=sk-... VLM_MODEL=gpt-4o-mini
export VLM_PROVIDER=anthropic VLM_API_KEY=sk-ant-...
export VLM_PROVIDER=ollama VLM_MODEL=qwen2.5vl:7b

```

Переменные: `VLM_PROVIDER`, `_MODEL`, `_API_KEY`, `_BASE_URL`,
`_MAX_SIDE_PX`, `_MAX_UPLOAD_MB`, `_MAX_IMAGES`, `_API_TOKEN`.
Полный список — в `.env.example`.

## Границы применимости

- **Демо-данные синтетические.** В репозитории нет фотографий — вместо
  них крошечные PNG с текстовым описанием сцены. Качество на реальных
  снимках зависит от выбранной модели и проверяется на ваших данных.
- **№3 не заменяет инженера по охране труда**, а ранжирует кадры для
  него: спорные наблюдения идут в отдельный список `needs_review`.
- **№7 не даёт медицинских рекомендаций**, оценка порции ±30%.
- **№8** — вспомогательный инструмент, а не средство обеспечения
  безопасности; он не заменяет трость и собаку-поводыря.
- **№12** блокирует шаги у опасных узлов (конденсаторы, сеть,
  аккумуляторы) до подтверждения обесточивания и разрядки.
- Кадры не сохраняются: сервис держит их в памяти на время запроса.
  Хранение и журнал прогонов — отдельная задача, если понадобятся.

## Тесты

`make test` — 178 проверок без сети и ключей:

- **изображения** — форматы, лимиты, отказ от загрузки по URL (SSRF),
  уменьшение крупных кадров, устойчивость к битым данным;
- **ядро** — разбор ответов модели, приведение «12,5» и «~3 шт» к числам,
  валидация имён параметров, изоляция оффлайн-подсказок от реальных
  провайдеров;
- **сервисы** — предметные инварианты: доля полки, WCAG-контраст,
  калории по Этуотеру, блокировка опасных шагов ремонта, маршрутизация
  спорной модерации человеку, две вилки оценки антиквариата;
- **API** — контракты, multipart, 400 на опечатки и чужие форматы,
  авторизация;
- **интерфейс** — синтаксис JS и рендер markdown в node с проверкой
  экранирования HTML.
