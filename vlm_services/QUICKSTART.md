# Быстрый старт

От нуля до работающего сервиса — 5 минут. Дальше по разделам: проверка на
своих фото, подключение реальной модели, вывод в прод.

---

## 1. Запуск за минуту (без ключей и без сети)

```bash
cd vlm_services
make install          # создаст .venv и поставит зависимости
make test             # 212 проверок, ~2 с — убедиться, что всё цело
make serve            # http://127.0.0.1:8081
```

Откройте `http://127.0.0.1:8081`, выберите любой из двенадцати сервисов и
нажмите **«Демо-данные»**. Отчёт появится сразу.

Провайдер по умолчанию — `fake`: встроенная оффлайн-модель. Она отвечает
по описанию сцены, приложенному к демо-кадру, поэтому вся логика сервиса
(пороги, арифметика, формулировки) работает по-настоящему, но ни одного
запроса наружу не уходит и ни копейки не тратится.

Проверить окружение:

```bash
make doctor
```

## 2. Первый запуск на своих фотографиях

Пока провайдер `fake`, модель не «видит» ваш файл — она вернёт пустой
каркас. Чтобы получить осмысленный результат, нужен настоящий VLM.

```bash
export VLM_PROVIDER=openai
export VLM_API_KEY=sk-...
export VLM_MODEL=gpt-4o-mini        # дешёвая модель, хватает для большинства задач

.venv/bin/vlm run pim-cards товар1.jpg товар2.jpg -p marketplace=ozon
.venv/bin/vlm run nutrition-plate обед.jpg
.venv/bin/vlm run retail-audit полка.jpg -p our_brand=Аква -p min_sos_pct=40
```

Стоимость и время печатаются в конце:

```
— 3.42 с, модель gpt-4o-mini, изображений 2, $0.0031
```

Через веб-интерфейс: перетащите фото в поле загрузки, при необходимости
поправьте JSON с параметрами и нажмите «Запустить».

## 3. Какие параметры принимает сервис

```bash
.venv/bin/vlm list                       # все двенадцать
curl -s localhost:8081/api/services/retail-audit | jq '.params, .demo_params'
```

Опечатка в имени параметра — ошибка, а не тишина:

```
$ vlm run retail-audit полка.jpg -p min_sos_pc=40
ошибка: retail-audit: неизвестные параметры: min_sos_pc.
        Доступные: min_sos_pct, our_brand, planogram
```

Так сделано намеренно: молча проглоченный `min_sos_pc` дал бы ответ с
порогом по умолчанию, а вы бы считали, что задали свой.

## 4. Вызов из своего кода

**REST, загрузка файлов:**

```bash
curl -X POST localhost:8081/api/services/retail-audit/upload \
     -F files=@полка.jpg \
     -F 'params={"our_brand":"Аква","min_sos_pct":40}'
```

**REST, серверная интеграция (data-URI):**

```python
import base64, requests

img = base64.b64encode(open("полка.jpg", "rb").read()).decode()
r = requests.post(
    "http://localhost:8081/api/services/retail-audit/run",
    json={"images": [f"data:image/jpeg;base64,{img}"],
          "params": {"our_brand": "Аква"}},
    headers={"Authorization": "Bearer ВАШ_ТОКЕН"},
)
print(r.json()["data"]["our_sos_pct"], r.json()["cost_usd"])
```

**Прямо из Python, без HTTP:**

```python
from vlmkit import run_service

res = run_service("nutrition-plate", ["обед.jpg"], daily_kcal=1800)
print(res.data["totals"]["kcal"], res.warnings)
```

Полная схема API — на `http://localhost:8081/docs`.

## 5. Вывод в прод

### Шаг 1. Обязательный минимум

```bash
cp .env.example .env
python3 -c "import secrets; print('VLM_API_TOKEN=' + secrets.token_urlsafe(32))" >> .env
```

Без `VLM_API_TOKEN` сервис слушает **только localhost** и откажется
стартовать на внешнем адресе. Это защита от главной ошибки: открытый
эндпоинт, который тратит ваши деньги на токены, находят за часы.

Поставьте потолок расходов — он спасает при зацикленном клиенте или
утёкшем ключе:

```bash
echo "VLM_DAILY_BUDGET_USD=50" >> .env
```

При исчерпании лимита сервис отвечает `402`, а не разоряет вас молча.

### Шаг 2. Запуск

```bash
docker compose up -d
curl localhost:8081/health
```

База (журнал прогонов и кеш) живёт в томе `vlm-data`, пересборка образа
её не трогает.

### Шаг 3. TLS

Сервис не терминирует HTTPS. Поставьте перед ним nginx — готовый пример
в `deploy/nginx.conf.example`, там уже учтены два подводных камня:
`client_max_body_size 25m` (фото с телефона) и `proxy_read_timeout 180s`
(VLM отвечает не мгновенно).

### Без Docker (systemd)

```bash
sudo useradd --system --home /opt/vlm-services vlm
sudo mkdir -p /opt/vlm-services /etc/vlm-services
sudo cp -r . /opt/vlm-services && cd /opt/vlm-services
sudo python3 -m venv .venv && sudo .venv/bin/pip install ".[all]"
sudo cp .env.example /etc/vlm-services/env && sudo chmod 600 /etc/vlm-services/env
sudo cp deploy/*.service deploy/*.timer /etc/systemd/system/
sudo systemctl enable --now vlm-services vlm-purge.timer
```

## 6. Сколько это стоит и как платить меньше

Провайдеры берут деньги за пиксели и токены. В сервисе три механизма
экономии, все включены по умолчанию.

**Сжатие изображений.** Фото 4000×3000 (184 КБ) ужимается до 1024×768
(4.8 КБ) — payload в 38 раз меньше. Деталей мельче 1024 px модель всё
равно не различает, так что качество ответа не страдает.

```bash
VLM_MAX_SIDE_PX=1024     # уменьшите до 768, если задача крупная (полка, план)
```

**Кеш по содержимому.** Один и тот же кадр с теми же параметрами стоит
один вызов, а не десять: мобильный клиент переотправляет фото при
ретраях, оператор открывает карточку повторно. Ключ считается по sha256
изображений, параметрам, провайдеру и модели.

```bash
vlm stats
# из кеша:           142 (38%)
# сэкономлено кешем: $1.87
```

**Выбор модели.** `gpt-4o-mini` в 16 раз дешевле `gpt-4o`. Начинайте с
неё и повышайте только там, где качество реально не устраивает.

Ориентир: одно фото 1024 px ≈ 1000–1500 входных токенов. На `gpt-4o-mini`
это примерно **$0.0003 за изображение**, то есть ~$3 за 10 000 снимков.

## 7. Наблюдение за работой

| команда / ручка | зачем |
|---|---|
| `vlm stats` | траты, доля кеша, разбивка по сервисам |
| `vlm runs --status error` | что падало и почему |
| `GET /health` | liveness для оркестратора |
| `GET /metrics` | Prometheus: траты, кеш, длительность |
| `GET /api/stats` | то же в JSON |

На что смотреть в первую очередь:

- **`vlm_spend_24h_usd` растёт быстрее ожидаемого** — кто-то гоняет
  дорогую модель или отключил кеш;
- **`vlm_cache_hit_rate` близка к нулю** — клиенты шлют каждый раз новые
  кадры (это нормально) либо передают `no_cache`;
- **доля `error` растёт** — смотрите `vlm runs --status error`; чаще
  всего это исчерпанная квота провайдера или недоступность API.

Каждый ответ несёт `X-Request-ID`; свой идентификатор можно передать тем
же заголовком, чтобы связать наш журнал с вашими логами.

Чистка старых записей (в systemd делается таймером раз в неделю):

```bash
vlm purge --older-than-days 30
```

## 8. Частые вопросы

**Ответ пустой или бессмысленный.** Проверьте `vlm doctor`: скорее всего
провайдер остался `fake`. Оффлайн-модель не смотрит на реальные пиксели.

**`402 дневной лимит исчерпан`.** Сработал предохранитель
`VLM_DAILY_BUDGET_USD`. Поднимите потолок или дождитесь следующих суток.

**`400 слишком много изображений`.** У каждого сервиса свой предел
(`GET /api/services/{slug}` → `max_images`): карточка товара принимает 3
фото, аудит полки — 6.

**`413` от nginx.** Увеличьте `client_max_body_size` и согласуйте с
`VLM_MAX_UPLOAD_MB`.

**Медленно.** Одно изображение — это секунды у любого провайдера.
Уменьшите `VLM_MAX_SIDE_PX`, шлите меньше кадров за раз или возьмите
модель полегче.

**Нужно без интернета.** `VLM_PROVIDER=ollama` с локальной моделью
(`qwen2.5vl:7b`) — интерфейс и API не тянут ничего с CDN и работают в
закрытом контуре.
