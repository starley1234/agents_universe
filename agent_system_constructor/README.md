# Среда агентов на LangChain + LangGraph

Семь продуктовых пайплайнов из `tz.txt`. Каждый — граф LangGraph, где
узлы это либо агенты (LLM с ролью и схемой ответа), либо детерминированные
инструменты (геометрия, арифметика тарифа, сопоставление спектров).

Работает **без ключей и без сети**: провайдер по умолчанию — оффлайн-модель
`fake`, поэтому весь набор проходится и тестируется локально.

```bash
make install
make test        # 54 проверки, < 1 с
python -m aconstructor run energy-hacker
```

## Принцип: LLM переводит, а не считает

Это главное архитектурное решение среды. Числа, деньги, геометрия и
юридические вердикты считаются кодом; модель формулирует признаки,
объясняет решение и пишет текст.

- **№1** — LLM разбивает формулу патента на признаки, но покрытие считает
  `textutil.coverage`, и степень риска выводится из измеренного покрытия,
  а не из настроения модели. Вердикт без обоснования отбрасывается.
- **№2** — совпадение детали считается по взвешенным физическим параметрам с
  допусками. Отсутствующий у поставщика параметр штрафуется мягче прямого
  расхождения: в мусорных прайсах половину характеристик не пишут.
- **№3** — топологию графа строит геометрия (привязка концов линий к
  штуцерам), а не модель: галлюцинация в трубопроводе попала бы в BIM.
  Импульсные линии КИП врезаются в трубу, а не в аппарат, и обрабатываются
  отдельно.
- **№4** — предложения диспетчера проверяются на технологические окна и
  добиваются жадным перебором; экономия считается по формуле тарифа.
- **№5** — пик опознаётся по времени удерживания и масс-спектру, потому что
  галлюцинация в CAS-номере стоит партии сырья.
- **№7** — отступы вычитаются из габарита, посадка проверяется по высоте,
  парковке и инсоляции.

### Про деньги в отчётах

Экономия считается честно: плата за мощность выставляется помесячно,
энергия — посуточно, поэтому годовой эффект это
`энергия × рабочие дни + мощность × 12`, а не «экономия за сутки × 250».
На этом легко завысить цифру в разы — под performance-based контракт
такое не годится. Тест `test_energy_annualization_does_not_multiply_monthly_demand_charge`
фиксирует правило.

## Как устроено

```
aconstructor/
  config.py      Settings: провайдер, модель, ключи, каталоги
  llm.py         фабрика LLM + EchoChatModel (оффлайн-заглушка)
  core.py        BaseState, Agent, Pipeline, реестр, run_pipeline
  textutil.py    детерминированные метрики сходства
  data/samples.py демо-данные для всех семи
  pipelines/     семь модулей, каждый регистрирует себя сам
```

Общее состояние (`BaseState`) одинаково у всех: `task`, `trace`,
`artifacts`, `findings`, `errors`, `report`. Поэтому логирование, отчёты и
выгрузка артефактов написаны один раз.

Агент декларируется схемой ответа:

```python
LEGAL = Agent(
    name="legal_llm",
    system="Ты патентный поверенный...",
    schema_hint={"risk": "medium", "rationale": "", "exposure_usd": 0},
)
```

`schema_hint` делает две вещи: подсказывает модели форму ответа и служит
скелетом, который возвращает оффлайн-провайдер — так граф проходится
целиком в CI. Разбор ответа терпит ```-обёртки и болтовню вокруг JSON;
если модель ответила мусором, узел падает в `errors`, а не роняет граф.

### Свой пайплайн

```python
from aconstructor import Agent, BaseState, Pipeline, register
from langgraph.graph import StateGraph, START, END

def build(cfg=None):
    g = StateGraph(BaseState)
    g.add_node("analyze", my_node)
    g.add_edge(START, "analyze"); g.add_edge("analyze", END)
    return g.compile()

register(Pipeline(slug="my-thing", title="…", summary="…",
                  build=build, demo_task=lambda: {...}))
```

Добавьте имя модуля в `pipelines/__init__.py:MODULES` — он подхватится
реестром, CLI и параметризованными тестами.

## Границы применимости

Стоит знать до продакшна:

- **Данные демонстрационные.** Номера патентов, компании, цены и кадастровые
  номера вымышлены. Реальные коннекторы (USPTO API, прайсы поставщиков,
  Росреестр, рынок РСВ) не подключены — это точка расширения `data/`.
- **№1 не заменяет патентного поверенного.** Покрытие признаков — это
  скрининг для приоритизации, а не FTO-заключение.
- **№3** работает по уже векторизованному слою; реальное распознавание
  растровой синьки (CV-модель) — отдельная задача перед этим графом.
- **№5** сопоставляет по RT и m/z; RT зависит от колонки и метода, поэтому
  на реальных данных нужна калибровка по эталонам, а совпадение
  масс-спектра — не доказательство структуры.
- **№7** использует упрощённые нормы (коэффициент застройки, тень = высота
  × 1.2). Для сделки нужен ГПЗУ и расчёт инсоляции по СанПиН.

модели, и предметные инварианты — что нерелевантный патент не всплывает,
что несдвигаемая операция остаётся на месте, что запрещённый IFRA
компонент исчезает из рецептуры, что скрипт Revit компилируется, а скобки
AutoLISP сбалансированы.
