# agents_universe

**Мультипарадигмальная лаборатория независимых проектов ИИ-агентов**

`agents_universe` — это репозиторий-исследовательская лаборатория, объединяющая **несколько совершенно независимых проектов** об автономных агентах, многоагентных системах, визуальных сервисах (VLM) и инструментариях.

**Каждый проект в этом репозитории — отдельная, самостоятельная реализация со своей собственной философией, архитектурой и стеком технологий.** Общего кода и жестких взаимных зависимостей в рантайме между ними нет:
- Ни один проект не диктует единую догму для остальных.
- Здесь исследуются и сравниваются **разные подходы и разные реализации**: от ультралегковесных ядер на чистой стандартной библиотеке Python (`stdlib`) и декларативных конструкторов — до корпоративных платформ интеграции данных, специализированных VLM-сервисов, а также экосистемных решений и экспериментов с фреймворками (**LangChain**, **LangGraph**, **FastAPI**, **MCP / Model Context Protocol**, **Pydantic** и др.).

## Архитектурные парадигмы и реализации

В этом репозитории намеренно нет единого «правильного» шаблона. Напротив, здесь исследуются альтернативные инженерные парадигмы:

1. **Легковесные ядра на чистом `stdlib` (`agent_system`, `agent_system_simple`, `agentic_workflow_os`)**:
   - Исследуют предел возможностей стандартной библиотеки Python без внешних зависимостей. Отличаются нулевым временем старта, полной прозрачностью стека и детерминированным контролем исполнения.
2. **Универсальные многопротокольные реестры и адаптеры (`agent_toolkit`)**:
   - Исследуют построение умного поискового каталога инструментов, который может одновременно обслуживаться через **Python SDK**, **REST API (FastAPI)**, протокол **MCP (Model Context Protocol)** и подключаться через адаптеры к фреймворкам типа **LangChain** или **OpenAI Function Calling**.
3. **Декларативные конструкторы и фабрики (`agent_system_constructor`)**:
   - Исследуют подход, при котором вся конфигурация агента, его подсказки, роли и маршрут выполнения описываются строго в JSON/YAML схемах.
4. **Корпоративные системы с транзакционными БД (`data_forge`, `erp_ai`, `multi_agent_system_ontology`, `saps`)**:
   - Исследуют работу агентов в реальных предметных областях с требованиями к аудиту, откату транзакций, векторному поиску (`pgvector`) и интеграции со справочниками (1С, Teamcenter, ERP).
5. **Мультимодальные зрительные сервисы (`vlm_services`)**:
   - Исследуют обработку визуальной информации (фотографии полок, скриншоты интерфейсов, сканы чеков и чертежей) с арифметической самопроверкой результатов.

## Как запустить и попробовать любой проект

Каждый проект автономен. Перейдите в папку интересующего вас проекта и воспользуйтесь командами его `Makefile`:

```bash
# 1. Запустить автотесты любого проекта
cd agent_toolkit && make test                  # 326 проверок
cd nexus_twin_mdm && make test                 # 24 проверки
cd agent_system && make test                   # 896 проверок
cd agentic_workflow_os && make test            # 493 проверки

# 2. Попробовать демонстрацию или интерактивный режим (где предусмотрено)
cd agentic_workflow_os && make demo            # Демонстрация цикла качества в AWOS
cd saps && make demo                           # Демонстрация сертификации авиатехники
cd agent_toolkit && make serve                 # Запуск REST API и Web UI на порту 8090
```

## Направления для экспериментов и улучшения (Proposals)

### Общие предложения для лаборатории `agents_universe`:
1. **Эксперименты с LangChain / LangGraph / LlamaIndex**:
   - Создать в репозитории новый экспериментальный проект (например, `langchain_agent_hub` или `langgraph_orchestrator`), чтобы практически сравнить скорость разработки, отладку, производительность и потребление токенов между фреймворками и нашими реализациями на чистом `stdlib`.
2. **Единая шина инструментов через Model Context Protocol (MCP)**:
   - Использовать проект **`agent_toolkit`** в качестве центрального MCP-сервера (`http://localhost:8090/api/mcp/rpc`), чтобы любые агенты из `agent_system`, `awos` или новых экспериментов на LangChain могли удалённо подключать весь каталог из 116 инструментов.

### Точечные предложения для развития каждого проекта и рекомендуемые инструменты:
- **`agent_toolkit`**:
  - *Веб-инструменты и браузерная автоматизация*: интеграция с Playwright / Puppeteer (`web.playwright_session`), извлечение микроразметки Schema.org (`web.extract_schema_org`), полноразмерные скриншоты (`web.capture_full_screenshot`), менеджер сессий и cookie (`web.cookie_session_manager`).
  - *САПР и инженерные расчёты*: экспорт моделей в обменный формат STEP / IGES (`cad.generate_step_file`), упрощённый конечно-элементный анализ напряжений FEA (`cad.simulate_fea_stress`), тепловой расчёт радиаторов (`physics.calc_thermal_dissipation`).
  - *Данные и PLM*: прямые коннекторы к PostgreSQL/MySQL (`db.postgres_execute`), вычисление формул Excel (`data.excel_formula_eval`), создание базовых линий требований в Teamcenter (`tc.create_requirement_baseline`).
- **`agent_system`**: добавить поддержку асинхронного выполнения длительных фоновых shell-команд (`shell.run_background`).
- **`agent_system_constructor`**: создать визуальный веб-редактор пайплайнов (Drag-and-Drop JSON Builder).
- **`agent_system_simple`**: добавить поддержку потоковой генерации ответов (Server-Sent Events / SSE) для WebIO.
- **`agentic_workflow_os` (`awos`)**: реализовать параллельные ветки исполнения шагов рабочего процесса (Fork-Join Steps).
- **`data_forge`**: добавить встроенную инспекцию форматов Parquet и DuckDB для аналитики больших таблиц.
- **`erp_ai`**: реализовать автоматическое сопоставление счетов и платежей по OData-интерфейсу 1С.
- **`multi_agent_system_ontology` (`maos`)**: внедрить механизм рефлексии (самопроверки агентом своего ответа перед выдачей роутеру).
- **`nexus_twin_mdm`**: добавить автоматический двусторонний обмен мастер-данными с 1С:ERP и Teamcenter по OData/REST с авто-генерацией сертификационных протоколов АП-25 и проверкой ЭЦП в бейслайнах.
- **`saps`**: добавить проверку электронных цифровых подписей (ЭЦП) в сертификационных документах.
- **`vlm_services`**: добавить обработку видеопотока (Video VLM) для мониторинга выкладки товаров в динамике.
