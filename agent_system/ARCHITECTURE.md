# Как это работает

## Ответы коротко

| вопрос | ответ |
|---|---|
| Пойдёт на Debian 1 ГБ? | **Да.** Измерено: 24 МБ RSS, 1 поток |
| Веб-морда? | **Есть**, `http://сервер:8080/` |
| На чём? | Python stdlib + один HTML-файл. **Ноль зависимостей** |
| Модель для 16 ГБ VRAM | **Devstral Small 2 22B** (Q4, ~14 ГБ, 128K окно) |
| Масштабируется на другие домены? | Да, через профили и наборы навыков |
| Экономия токенов | Измерено **−74 %** контекста |

---

## 1. Debian 1 ГБ

Замер на этой машине:

```
VmRSS:   24 528 kB      ← сервер с загруженными профилями
VmPeak:  32 720 kB
Threads: 1
```

Занимает ~2,5 % от гигабайта. Причина простая: нет ни фреймворка, ни
ORM, ни Node — только стандартная библиотека Python.

Важная оговорка: **модель на этом сервере не поместится.** 1 ГБ — для
самого агента. Модель живёт либо в облаке (OpenRouter), либо на вашей
второй машине с GPU. Агент — тонкий клиент.

Если включите `sandbox: docker`, память съест уже Docker, а не агент.
На 1 ГБ разумнее `sandbox: "confirm"`, а изоляцию держать на уровне
самой VM.

---

## 2. На чём сделана веб-морда

**Один файл** `agent/web/index.html`, 6,8 КБ: HTML + CSS + ~120 строк
ванильного JS. Ни React, ни сборки, ни `node_modules`.

Почему так: фреймворк здесь дал бы 200 МБ зависимостей и шаг сборки
ради формы ввода и списка сообщений. Ваш принцип «просто и лаконично»
на 1 ГБ читается однозначно.

Что умеет: выбор роли, поле рабочей папки, токен, поток событий в
реальном времени (вызовы инструментов сворачиваются в раскрывающиеся
блоки), кнопка «Стоп».

Открывается на `/`. Страница отдаётся без токена — она пустая
оболочка, все данные требуют `Authorization`.

## 3. Как работает система

### Цикл

```
задача
  ↓
[ модель ] ←──────────────┐
  ↓ хочет инструменты?    │
  ├─ да → выполнить → результат в историю ─┘
  └─ нет → ответ, конец
```

Ядро — `agent/core.py`, ~200 строк. Три вещи, ради которых там код,
а не десять строк:

1. **Ошибка инструмента не роняет агента.** Текст ошибки уходит модели,
   она получает шанс исправиться. Проверено диверсией: если убрать этот
   перехват, тест падает с трейсбеком.
2. **Лимит шагов.** По исчерпании — честный отчёт «не доведено до
   конца», а не тихий обрыв.
3. **Управление контекстом** — см. раздел про токены.

### Слои

```
CLI / HTTP API / Web
        ↓
   Agent (цикл)
    ↓        ↓
  LLM     ToolRegistry
 драйвер   ↓
          Workspace (изоляция путей)
```

Ядро не знает ни про провайдеров, ни про домен задачи. Провайдер —
драйвер, домен — профиль.

## 4. Как выбираются агенты и как оркеструются

Здесь важно быть точным: **это не мультиагентная система с роями.**
Один цикл, один набор инструментов на запуск. Так надёжнее и дешевле.

«Выбор агента» = **выбор профиля**. Профиль — JSON из трёх полей:
роль (системный промпт), набор навыков, лимит шагов.

```json
{
  "name": "cad",
  "skills": ["files", "shell", "cad"],
  "max_steps": 60,
  "system_prompt": "Ты инженер-конструктор…"
}
```

Готовые: `coder`, `cad`, `research`, `marketing`.

```bash
python3 -m agent -P cad "проверь сборку редуктора"
python3 -m agent -P marketing "лендинг для планетарного редуктора"
```

Разница видна сразу: у `cad` 11 инструментов, у `marketing` — 5,
без `shell`. Маркетологу shell не нужен, а лишний инструмент — это
лишний соблазн и лишние токены в описании.

### Оркестрация нескольких ролей

Через HTTP API: профиль и рабочая папка задаются **в каждом запросе**,
поэтому один сервис обслуживает разные проекты и роли.

```bash
curl -X POST localhost:8080/run -H "Content-Type: application/json" \
  -d '{"profile":"research","workspace":"/data/proj1","task":"собери выжимку"}'

curl -X POST localhost:8080/run -H "Content-Type: application/json" \
  -d '{"profile":"marketing","workspace":"/data/proj1","task":"по выжимке — три оффера"}'
```

Конвейер строится снаружи — обычным скриптом или cron. Это осознанный
выбор: цепочка из bash прозрачна и отлаживается, а «агент, который
руководит агентами» на практике жжёт токены и прячет ошибки.

## 5. Модель для 16 ГБ VRAM (LM Studio)

По актуальным данным на середину 2026:

| модель | VRAM (Q4) | окно | почему |
|---|---|---|---|
| **Devstral Small 2 22B** ★ | ~14 ГБ | **128K** | заточена под агентные циклы, 52,3 % SWE-bench Verified, Apache 2.0 |
| Qwen3-Coder 30B-A3B | ~18–19 ГБ | 256K | MoE, активны 3 Б параметров; на 16 ГБ только с выгрузкой |
| gpt-oss 20B | ~14 ГБ | 128K | безопасный запасной вариант |
| Codestral 22B | ~14 ГБ | 32K | **лицензия MNPL запрещает коммерческое применение** |

**Рекомендую Devstral Small 2 22B.** Она сделана именно под то, что
делает наш агент: многошаговые правки, вызов инструментов,
восстановление после ошибок. Apache 2.0 — можно коммерчески.

Окно: ставьте **32K, не 128K**. Причина — KV-кэш. При 128K он съест
несколько гигабайт и вытеснит саму модель. Наши задачи с включённой
экономией укладываются в 8–16K.

```bash
# LM Studio: включите OpenAI-совместимый сервер, затем
python3 -m agent -p lmstudio -m devstral-small-2 \
  --base-url http://GPU-СЕРВЕР:1234/v1 -P coder "задача"
```

Проверьте, что модель реально умеет tool calling: без этого агент
работать не будет — он весь построен на вызовах инструментов.

## 6. Экономия токенов

Три механизма, все измерены.

**Обрезка результата инструмента** (`tool_result_limit: 4000`).
В историю идёт голова и хвост, середина вырезается. `cat` большого
файла больше не съедает окно.

**Свёртка старых результатов** (`keep_last_results: 3`). Полностью
хранятся только последние N результатов — с ними модель работает
сейчас. Старые сворачиваются в строку «[свёрнуто, 40000 символов]».
Факт вызова сохраняется, простыня — нет.

**Урезание истории** по общему объёму, с сохранением системного
промпта и задачи.

Замер на реальном цикле (8 чтений большого файла):

```
БЕЗ экономии   61 196 символов  (~15 300 токенов)
С экономией    15 729 символов  (~ 3 900 токенов)   −74 %
```

### Что ещё экономит

- **Профиль под задачу.** `marketing` даёт 5 инструментов вместо 11 —
  схемы инструментов уходят в каждый запрос.
- **`temperature: 0`** (уже стоит) — меньше блужданий, меньше шагов.
- **Локальная модель для черновиков**, OpenRouter — для сложного.
  Переключение флагом `-p`.
- **Дешёвая модель на простое.** На OpenRouter разница между моделями
  десятикратная; ставьте сильную только туда, где она нужна.
- **Конкретная задача.** «Почини тест X в файле Y» вместо «разберись
  с проектом» экономит больше, чем все технические меры вместе.

## 7. Оценка функционала и что добавить

### Что уже хорошо

- ядро не зависит ни от провайдера, ни от домена;
- изоляция рабочей папки проверена, включая симлинки;
- ошибки инструментов не роняют цикл;
- 98 проверок, из них 14 сквозных на реальных сокетах;
- **тесты проверены на чувствительность** — вносили дефекты, тесты их
  ловили;
- ноль зависимостей.

### Чего не хватает, по убыванию пользы

**1. Память между запусками.** Сейчас каждый запуск начинается с нуля.
Простое решение в вашем стиле: файл `NOTES.md` в рабочей папке, который
агент читает в начале и дописывает в конце. Без базы и векторов.

**2. Учёт токенов и стоимости.** Провайдеры возвращают `usage`, мы его
не читаем. Стоит показывать в конце каждого запуска — при работе с
OpenRouter это прямые деньги.

**3. Повтор при сбое сети.** Одна ошибка соединения сейчас завершает
задачу. Три попытки с паузой закрыли бы 90 % случаев.

**4. Журнал запусков.** JSONL с задачей, шагами и результатом. Нужен,
чтобы разбирать, почему агент пошёл не туда.

**5. Ограничение на файлы.** Агент может прочитать 100-мегабайтный лог
и выжечь окно. Лимит на размер читаемого файла.

Каждый пункт — 20–60 строк. Могу добавить, скажите какие.

### Чего добавлять НЕ советую

- **Роя агентов.** Умножает стоимость и делает отладку невозможной.
- **Векторной базы.** Для рабочей папки `search_text` работает лучше и
  честнее: он не «примерно похоже», а точное совпадение.
- **Тяжёлого веб-фреймворка.** На 1 ГБ это прямой проигрыш.

## 8. Масштабирование на разные решения

Да, база подходит. Проверено на двух крайних доменах: `cad`
(11 инструментов, shell, OpenSCAD) и `marketing` (5 инструментов, без
shell) — оба собираются и работают в одном ядре.

**Инженерное бюро.** Готов профиль `cad`. Проверки геометрии перенесены
из реального проекта планетарного редуктора: булевы коллизии с оценкой
объёма, водонепроницаемость STL, связность.

**Маркетинговое агентство.** Профиль `marketing` есть. Стоит добавить
навык `web` (поиск и загрузка страниц) — это ~60 строк на `urllib`.

**Своё направление** — два шага:

1. модуль с `build(ws) -> list[Tool]`, строка в `SKILLS`;
2. JSON-профиль в `agent/profiles/`.

Ядро, изоляция, экономия токенов, веб-морда и API достаются готовыми.

Честная граница: система рассчитана на задачи в **одной рабочей папке**
с проверяемым результатом. Для длинных бизнес-процессов с состоянием и
согласованиями нужен слой оркестрации снаружи — здесь его нет намеренно.
