# Агентная система

Автономный агент с инструментами: читает и правит файлы, запускает
команды, создаёт документы, ищет по памяти, проверяет результат
и честно докладывает, что не вышло. Работает на вашем сервере.

**Зависимостей нет** — только стандартная библиотека Python 3.10+.
`pip install` не нужен. Проверено: тесты зелёные и без `python-docx`,
`openpyxl`, `python-pptx`, `pypdf` — при их наличии качество выше.

**Требования:** Python 3.10+, Debian с 1 ГБ RAM хватает — измерено
27 МБ RSS.

```bash
python3 -m agent --do "почини падающий тест в calc.py"
```

`--do` — простой режим: систему не надо знать, она сама выберет роль
и объяснит выбор.

## Быстрый старт

```bash
make test                     # 723 проверки, ~40 с
export AGENT_PROVIDER=ollama AGENT_MODEL=devstral-small-2:22b
python3 -m agent --check      # самопроверка окружения
python3 -m agent --do "разбери договоры из in/ и собери реестр в xlsx"
```

| команда | что делает |
|---|---|
| `agent --do "…"` | роль и режим выбираются сами |
| `agent -P coder "…"` | явная роль |
| `agent` | интерактивный режим |
| `agent --auto --hours 6 --max-usd 5 "цель"` | автономная работа |
| `agent --auto --route "цель"` | каждый пункт плана своему агенту |
| `agent --runs` / `--runs 7` | история прогонов |
| `make serve` | веб-интерфейс на `127.0.0.1:8080` |

## Чем это отличается

**Молчание не считается успехом.** Пустой вывод тестов — «прогонщик не
запустился», а не «всё хорошо». Письмо без белого списка не уходит и
прямо говорит: «Не считай это выполненной отправкой». Вопрос без ответа
блокирует пункт плана, а не закрывает его.

**Агент не выдумывает память.** Спросили о прошлом — либо `recall`,
либо честное «не помню, история не сохранялась».

**Откат есть.** Снимок рабочей папки делается перед каждым шагом,
`revert` возвращает как было, само состояние до отката тоже
сохраняется.

**Деньги под контролем.** Учёт по каждой модели, предел `--max-usd`,
маршрутизация «дешёвая на рутину, сильная на сложное».

**Девять провайдеров** — OpenAI, Anthropic, Ollama, OpenRouter, vLLM,
LM Studio, llama.cpp и совместимые. Повтор при сбое связи: 429 и 5xx
повторяются, 401 и 400 — нет.

## Безопасность

- **Рабочая папка.** Любой путь от модели проверяется после `resolve()`,
  поэтому `..`, симлинки и абсолютные пути отсекаются одинаково.
- **Песочница.** `auto` — Docker, если он есть, иначе прямой запуск с
  подтверждением опасных команд. Жёсткий `docker` без демона раньше
  делал `run_command` мёртвым — теперь деградация с объяснением.
- **Отправка наружу.** Пустой белый список означает «никому», а не
  «всем». Маска `*@firma.ru` не пропускает `kto@firma.ru.evil.com`.
- **Секреты только в окружении.** Конфиг кладётся в git, `.env` — нет.
- **Веб наружу без токена не поднимется** — откажется при старте.

## Как это проверено

Тесты писались по тому же правилу, что и инженерные проверки:
**тест обязан уметь падать.**

```bash
make test        # 723 проверки (710 без дополнительных библиотек)
make test-e2e    # 14 проверок на настоящих сокетах
```

Проверяется не «функция вернула значение», а результат по существу:
документы **читаются обратно** сторонними библиотеками, письмо реально
уходит на настоящий SMTP-сервер, вопрос агента ждёт ответа из другого
потока, расход памяти на 5000 векторов замеряется.

Каждая критичная проверка подтверждена **диверсией** — код ломался
намеренно, тест обязан был упасть:

| внесённый дефект | сколько проверок упало |
|---|---|
| убрана проверка выхода за рабочую папку | 6 |
| ошибка инструмента роняет цикл | трейсбек |
| рассуждение принимается за результат | 2 |
| пустой ответ модели завершает задачу | 2 |
| цена берётся по первому совпадению ключа | 2 |
| ответ человека выдумывается, когда его нет | 7 |
| откат оставляет мусор или теряет работу | 2 |
| бюджет денег не проверяется | 6 |
| пустой запрос стирает всю память | 2 |
| пустой белый список означает «всем» | 2 |
| черновик молча ничего не делает | 7 |
| PDF без карты ToUnicode (кириллица бьётся) | 4 |
| числа в xlsx пишутся текстом | 1 |
| провал тестов виден только по коду возврата | 4 |
| устаревший `.pyc` не чистится перед прогоном | 2 |
| векторы разной размерности сравниваются | 1 |
| ответ уходит не тому вопросу | 2 |
| нет предела очереди вопросов | 2 |

Полный список — в разделах «Тесты» тематических документов.
После восстановления снова 723/723: «пройдено» здесь означает
работоспособность, а не отсутствие проверок.

`cad` проверен на настоящем OpenSCAD: пересечение 3000 мм³ опознано как
коллизия, касание гранью — как норма, разнесённые тела — как чисто.

## Структура

```
agent/
  core.py         цикл «модель → инструменты → модель»
  build.py        сборка агента из конфига
  config.py       конфигурация: профиль + файл + окружение + CLI
  dispatch.py     кто берёт задачу: выбор роли по тексту
  cli.py          командная строка
  server.py       HTTP API
  webio.py        вопросы агента через веб: ожидание ответа
  store.py        SQLite: память, онтология, план, история
  vectors.py      векторы в SQLite: поиск по смыслу
  autorun.py      автономный цикл: план → работа → рефлексия
  mcp.py          клиент MCP: stdio и http, лимиты частоты
  llm/            9 провайдеров + маршрутизация моделей
  tools/          files, shell, python, dev, vcs, ask, memory, …
  skills/         documents, makedocs, comms, rag, verify, cad, pg
  profiles/       13 ролей
  web/            index.html — интерфейс одним файлом
tests/            11 файлов, 723 проверки
docs/             тематическая документация
examples/         готовые конфигурации
docker/           образы агента и песочницы
```

## Установка и Docker

```bash
make install                  # ~/.local/bin/agent
make build && docker compose up -d
```

`docker-compose.yml` пробрасывает сокет докера, чтобы агент мог
поднимать песочницу, и открывает порт только на `127.0.0.1`.

## Чего пока нет

Честно, чтобы не было сюрпризов:

- **не проверено на живой модели в длинном прогоне** — вся логика на
  заглушках и настоящих сокетах, но восьмичасового прогона на настоящем
  LLM не было; первый запуск делайте на неважной папке с `-v`;
- планировщик разбивает задачу один раз;
- вызовы инструментов идут последовательно;
- очереди прогонов нет — один за раз;
- автономный режим запускается только из CLI, не из браузера;
- PDF-парсер не читает сканы (нужен OCR);
- Windows не поддержан: `resource`, пути и `bash -lc` рассчитаны на Linux.
