# Агентная система

Автономный агент с инструментами: читает и правит файлы, запускает
команды, проверяет результат. Запускается на вашем сервере.

**Зависимостей нет** — только стандартная библиотека Python 3.10+.
`pip install` не нужен.

---

**Требования:** Python 3.10+. Работает на Debian с 1 ГБ RAM —
измерено 24 МБ RSS.

**Начните с [OVERVIEW.md](OVERVIEW.md)** — как работает, как пользоваться,
честная оценка и разбор «нужен ли PostgreSQL + pgvector».

Подробно: [ARCHITECTURE.md](ARCHITECTURE.md) — устройство, выбор модели,
экономия токенов. [AUTONOMY.md](AUTONOMY.md) — автономная работа часами.

## Быстрый старт

```bash
cd agent_system
make test                     # 65 проверок, ~1 с
make build-sandbox            # образ песочницы (для sandbox=docker)

export OPENAI_API_KEY=sk-...
python3 -m agent --check      # самопроверка окружения
python3 -m agent "напиши скрипт сортировки и проверь его на тестах"
```

Интерактивный режим — без аргументов:

```bash
python3 -m agent
```

Веб-интерфейс и API:

```bash
make serve                    # http://127.0.0.1:8080/
```

Морда — один HTML-файл на ванильном JS, без сборки и зависимостей.

## Внешние сервисы (MCP)

Веб-поиск, загрузка страниц, картинки, речь — через **ваши MCP-серверы**
(те же, что в LM Studio). У каждого свой лимит частоты:

```json
"search": { "rate_limit": 20 },   // не чаще раза в 20 с
"fetch":  { "rate_limit": 0 }     // безлимитно
```

Недоступный сервер не ломает агента. Подробно — [MCP.md](MCP.md).

## Показ артефакта

Инструмент `present` собирает итог прогона в **одну HTML-страницу**:
сводка, план, выясненные факты, вложенные файлы (картинки вшиты в
base64). Открывается в браузере, самодостаточна.

## Автономный режим

Агент работает часами сам: планирует, копит знания в SQLite, строит
онтологию, рефлексирует, не зацикливается.

```bash
python3 -m agent --auto -P cad_auto --hours 8 "оптимизировать редуктор"
python3 -m agent --auto --resume 3        # продолжить после обрыва
```

Состояние — один файл `agent.db`: память с полнотекстовым поиском,
граф объектов и связей, план, журнал действий. Переживает перезапуск.

Подробно — [AUTONOMY.md](AUTONOMY.md).

## Роли (профили)

```bash
python3 -m agent -P cad       "проверь сборку узла"
python3 -m agent -P marketing "лендинг для редуктора"
python3 -m agent -P research  "выжимка по материалам в папке"
python3 -m agent -P coder     "почини падающий тест"
```

Профиль = роль + набор навыков + лимит шагов, файл в
`agent/profiles/*.json`. У `cad` 11 инструментов, у `marketing` — 5.

## Надёжность и расход

**Повтор при сбое связи.** Сеть моргнула или сервер ответил 503 —
агент подождёт (2, 4, 8 с) и повторит. Восьмичасовой прогон больше не
обрывается из-за одной ошибки. Ошибки настройки (401, 400) не
повторяются: это трата времени.

**Учёт токенов и денег.** После каждого запуска видно, сколько
израсходовано:

```
токенов: 12,480 (вход 11,200, выход 1,280), вызовов: 8  · примерно $0.0024
```

Для локальных моделей — «оплаты нет». Для неизвестных честно пишет
«цена неизвестна», а не выдумывает сумму. В автономном режиме расход
копится в базе по прогону.

## Экономия токенов

```json
"tool_result_limit": 4000,
"keep_last_results": 3
```

Длинные результаты обрезаются, старые сворачиваются в строку.
Измерено на цикле из 8 вызовов: **−74 % контекста**
(15 300 → 3 900 токенов).

## Выбор модели

Одна строка в конфиге или флаг. Поддержаны:

| провайдер | назначение |
|---|---|
| `openai` | OpenAI и любой совместимый шлюз |
| `openrouter`, `vllm`, `lmstudio`, `llamacpp` | те же, с готовым base_url |
| `anthropic` | Claude (Messages API) |
| `ollama` | локальные модели |

```bash
python3 -m agent -p ollama -m qwen2.5-coder:14b "задача"
python3 -m agent -c examples/config.anthropic.json "задача"
```

Ключи берутся из окружения (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`) —
в конфиг их класть не нужно, файл можно хранить в git.

## Безопасность

Агент выполняет команды, поэтому изоляция — не опция.

**`sandbox.mode: "auto"`** (по умолчанию) — есть Docker, работаем в
одноразовом контейнере; нет — на хосте с подтверждением опасных команд.
Без демона инструмент не отказывает, а деградирует, честно сообщая об
этом в выводе.

**`"docker"`** — каждая команда в одноразовом контейнере: сеть
выключена, лимиты CPU и памяти, наружу видна только рабочая папка.

**`"confirm"`** — прямой запуск, но опасные команды (`rm -rf`, `mkfs`,
`curl | sh`, fork-бомба и другие) требуют подтверждения оператора.

**`"off"`** — без ограничений, если изолируете сами.

Независимо от режима работают:

- **защита рабочей папки** — путь проверяется после `resolve()`, поэтому
  `..`, абсолютные пути и симлинки наружу отсекаются одинаково;
- **тайм-ауты** — зависшая команда не вешает агента;
- **обрезка вывода** — мегабайтный лог не засоряет контекст.

## Наборы навыков

```json
"skills": ["files", "shell", "cad"]
```

| набор | инструменты |
|---|---|
| `files` | `read_file`, `write_file`, `edit_file`, `list_files`, `search_text` |
| `shell` | `run_command` |
| `memory` | `remember`, `recall`, `note_entity`, `link`, `describe`, `plan_*` |
| `present` | `present` — итоговый HTML-отчёт |
| `mcp` | инструменты ваших MCP-серверов |
| `cad` | `scad_render`, `scad_export_stl`, `stl_check`, `stl_bbox`, `scad_collision` |

### Набор `cad`

Проверки, отработанные на реальном проекте планетарного редуктора.
Главный принцип: **не оценивать геометрию на глаз**.

- `scad_collision` — булево пересечение двух тел с **оценкой объёма**.
  Отличает реальное внедрение от касания по плоскости: у сопрягаемых
  деталей пересечение — лист нулевого объёма, и это норма.
- `stl_check` — водонепроницаемость (каждое ребро ровно в двух
  треугольниках) и число связных компонент. Ловит дыры и отвалившиеся
  части, невидимые на рендере.
- `stl_bbox` — реальные габариты и объём, чтобы сверять с расчётом.

### Свой набор навыков

Модуль с функцией `build(ws) -> list[Tool]` и одна строка в
`agent/build.py`:

```python
SKILLS = {
    ...,
    "mytools": lambda ws, cfg, confirm: mytools.build(ws),
}
```

## HTTP API

```
GET  /health         жив ли сервис (без токена)
GET  /info           конфигурация и список инструментов
POST /run            {"task": "..."} -> результат с трассировкой
POST /run/stream     то же, события построчно (NDJSON)
```

```bash
curl -X POST http://127.0.0.1:8080/run \
  -H "Authorization: Bearer $AGENT_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"task": "перечисли файлы и найди TODO"}'
```

Если `AGENT_API_TOKEN` не задан, сервер **отказывается** слушать
что-либо кроме `127.0.0.1` — чтобы открытый наружу агент не оказался
доступен без пароля.

В запросе можно переопределить `workspace`, `model`, `provider`,
`max_steps`, `skills` — удобно обслуживать несколько проектов одним
сервисом.

## Как это проверено

Тесты писались по тому же правилу, что и инженерные проверки:
**тест обязан уметь падать**.

```
make test        # 232 проверки (ядро + память + автономия + MCP)
make test-e2e    # 14 проверок на реальных сокетах
```

Покрыто: изоляция путей (включая симлинки), файловые операции, тайм-ауты
и обрезка вывода, детектор опасных команд, устойчивость цикла к ошибкам
инструментов, лимит шагов, обрезка истории, конфигурация, разбор STL.

Проверка чувствительности — вносили дефекты и убеждались, что тесты их
ловят:

| внесённый дефект | реакция |
|---|---|
| убрана проверка выхода за workspace | 6 падений |
| убрана защита от неоднозначной замены | 1 падение |
| ошибка инструмента роняет цикл | падение с трейсбеком |
| отключена свёртка старых результатов | 1 падение |
| обрезка теряет конец текста | 1 падение |
| цель не подставляется в итерацию | 1 падение |
| рефлексия не пишет в память | 1 падение |
| застой игнорируется | 2 падения |
| повтор при сбое отключён | падение с трейсбеком |
| 401 повторяется как временная ошибка | 2 падения |
| usage не читается из ответа | 4 падения |
| цена берётся по первому совпадению | 2 падения |
| reasoning_content игнорируется | 1 падение |
| пустой ответ завершает задачу | 2 падения |
| очистка пути отключена | 5 падений |
| рассуждение принимается за результат | 2 падения |
| флаг from_reasoning не выставляется | 1 падение |

После восстановления — снова 266/266. Значит «пройдено» здесь означает
работоспособность, а не отсутствие проверок.

Набор `cad` проверен на настоящем OpenSCAD: пересечение 3000 мм³
опознано как коллизия, касание гранью — как норма, разнесённые тела —
как чисто.

## Структура

```
agent/
  core.py           цикл «модель -> инструменты -> модель»
  build.py          сборка агента из конфига
  config.py         конфигурация: файл + окружение + CLI
  cli.py            командная строка
  server.py         HTTP API
  llm/              драйверы моделей (openai_like, anthropic, ollama)
  tools/            base (реестр, изоляция путей), files, shell
  skills/           cad_openscad
  mcp.py            клиент MCP: stdio и http, лимиты частоты
  store.py          SQLite: память, онтология, план, журнал
  autorun.py        автономный цикл: план → работа → рефлексия
  profiles/         роли: coder, cad, cad_auto, research, marketing, autonomous
  web/              index.html — веб-интерфейс
tests/              модульные и сквозной тесты
docker/             образы агента и песочницы
examples/           готовые конфигурации
```

```bash
make build

```

`docker-compose.yml` пробрасывает сокет докера, чтобы агент мог
поднимать песочницу, и порт только на `127.0.0.1`.
