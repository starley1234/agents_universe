# Что и где настраивать

Три места, больше нет:

| где | что там | попадает в git |
|---|---|---|
| **файл конфига** `config.json` | модель, навыки, адреса служб | да, можно хранить |
| **переменные окружения** | ключи, пароли, токены | **нет, никогда** |
| **профили** `agent/profiles/*.json` | роли агентов | да |

Приоритет: аргументы командной строки → переменные окружения → файл →
умолчания. Профиль применяется первым, всё заданное явно его перекрывает.

---

## Самый короткий путь

Ничего не настраивая, с локальной моделью:

```bash
export AGENT_PROVIDER=ollama
export AGENT_MODEL=devstral-small-2:22b
python3 -m agent --do "почини падающий тест в calc.py"
```

`--do` — простой режим: роль и режим работы выбираются сами (см. ниже).

Две разные проверки, и путать их не стоит:

```bash
python3 -m agent --check     # настройки, песочница, сборка агента
python3 -m agent --smoke     # ЖИВАЯ модель: тянет ли она инструменты
```

`--check` до модели не дотрагивается: «готово к работе» там означает
«настройки на месте». `--smoke` наоборот — гоняет модель по десятку
задач с проверяемым результатом.

## 1. Файл конфига

Указывается через `-c config.json`. Ключи с подчёркиванием (`"_моё"`) —
комментарии, JSON их не поддерживает, а пояснять настройки надо.
**Опечатка в ключе — ошибка с подсказкой**, а не молчаливое игнорирование.

### Минимум

```json
{
  "provider": "ollama",
  "model": "devstral-small-2:22b",
  "base_url": "http://localhost:11434",
  "workspace": "./workspace"
}
```

### Все ключи

| ключ | умолчание | зачем |
|---|---|---|
| `provider` | `openai` | openai, anthropic, ollama, openrouter, vllm, lmstudio, llamacpp |
| `model` | `gpt-4o-mini` | имя модели |
| `base_url` | по провайдеру | адрес API |
| `temperature` | `0.0` | разброс ответов |
| `workspace` | `./workspace` | **рабочая папка агента; за её пределы он не выйдет** |
| `max_steps` | `30` | предел шагов одного запуска |
| `skills` | files, shell, memory, present | набор инструментов |
| `profile` | — | роль, заменяет skills и промпт |
| `db` | `agent.db` | память, план, векторы, история |
| `system_prompt` | — | свой промпт вместо профильного |

**Экономия контекста**

| ключ | умолчание | зачем |
|---|---|---|
| `tool_result_limit` | `4000` | обрезка результата инструмента |
| `keep_last_results` | `3` | полностью хранить N последних |

**Автономный режим**

| ключ | умолчание | зачем |
|---|---|---|
| `max_hours` | `1.0` | бюджет времени |
| `max_iterations` | `50` | предел итераций |
| `max_usd` | `0` | **предел денег; 0 = без предела** |

**Песочница** (раздел `sandbox`)

| ключ | умолчание | зачем |
|---|---|---|
| `mode` | `auto` | auto → docker если есть, иначе confirm |
| `timeout` | `120` | предел команды, секунд |
| `memory` / `cpus` | `1g` / `2` | лимиты контейнера |
| `network` | `false` | сеть внутри контейнера |

**Прочее**

| ключ | умолчание | зачем |
|---|---|---|
| `vcs_auto` | `true` | снимок папки перед каждым шагом |
| `python_timeout` | `60` | предел `run_python` |
| `fetch_allow_private` | `false` | пускать в локальную сеть (защита от SSRF) |
| `model_cheap` + `model_strong` | — | **обе сразу** включают маршрутизацию |
| `route_long_context` | `12000` | порог перехода на сильную модель |
| `embed_url`, `embed_model`, `embed_dim` | — | служба векторов для поиска по смыслу |
| `pg_dsn` | — | PostgreSQL+pgvector, если записей больше ~5000 |

**Связь** (раздел `comms`) — подробности в [OFFICE.md](docs/OFFICE.md)

| ключ | зачем |
|---|---|
| `smtp_host`, `smtp_port`, `smtp_ssl`, `smtp_user`, `smtp_from` | отправка почты |
| `imap_host`, `imap_port`, `imap_user` | чтение почты |
| `allow_to` | **белый список получателей; пустой = никому** |
| `telegram_chat`, `max_chat` | чаты по умолчанию |
| `outbox` | папка черновиков, если отправка запрещена |

**MCP-серверы** (раздел `mcp`) — подробности в [MCP.md](docs/MCP.md)

### Готовые примеры

```
examples/config.ollama.json      локальная модель
examples/config.openai.json      OpenAI
examples/config.anthropic.json   Claude
examples/config.safe.json        осторожный запуск: снимки, вопросы, откат
examples/config.office.json      документы и рассылка
examples/config.cad.json         OpenSCAD
examples/config.docs.json        разбор документов
examples/config.mcp.json         внешние MCP-серверы
```

## 2. Переменные окружения

**В конфиге ключей нет и не должно быть.** Он кладётся в git.

```bash
# модель
export OPENAI_API_KEY=sk-...
export ANTHROPIC_API_KEY=sk-ant-...
export OLLAMA_HOST=http://localhost:11434

# быстрая замена без файла конфига
export AGENT_PROVIDER=ollama
export AGENT_MODEL=devstral-small-2:22b
export AGENT_PROFILE=coder
export AGENT_WORKSPACE=~/work
export AGENT_SANDBOX=confirm

# связь (навык comms)
export AGENT_SMTP_PASS=...      # пароль почты
export AGENT_IMAP_PASS=...      # если отличается от SMTP
export AGENT_TG_TOKEN=...       # Telegram
export AGENT_MAX_TOKEN=...      # MAX
```

Удобно держать в `~/.agentrc` и подключать `source ~/.agentrc`.

## 3. Профили

`agent/profiles/*.json` — роль это набор навыков плюс промпт.

| профиль | для чего |
|---|---|
| `coder` | код: правка, тесты, снимки, вопросы |
| `reviewer` | разбор чужой работы, только замечания |
| `ops` | диагностика сервера, **строго чтение** |
| `cad` / `cad_auto` | OpenSCAD, STL, коллизии |
| `office` | Word/Excel/PowerPoint/PDF и рассылка |
| `docs` | разбор входящих документов |
| `rag` | индексация и поиск по документам |
| `verify` | проверка комплектности и требований |
| `onto` | онтология, граф знаний |
| `research` | изучение темы, сравнение вариантов |
| `marketing` | тексты |
| `autonomous` | долгая работа без человека |

Свой профиль — файл рядом с этими, никакого кода.

## Простой режим: система сама решает, кто работает

```bash
python3 -m agent --do "сделай презентацию по итогам квартала"
```

```
Разбор задачи
  задача : сделай презентацию по итогам квартала
  выбран профиль «office» — совпали признаки темы (вес 3.0)
  режим  : одиночный запуск
  навыки : files, documents, makedocs, comms, memory, present

Начинать? [Enter — да, имя профиля — заменить, n — отмена]
```

Три вещи, ради которых это сделано именно так:

**Выбор объясняется вслух и его можно отменить.** Тихо назначить
исполнителя нельзя: если правило ошиблось, человек должен увидеть это
до начала работы, а не по итогам часа. Нажать Enter — согласиться,
написать имя профиля — заменить, `n` — отменить. `-y` пропускает вопрос.

**Выбор правилами, а не моделью.** Одинаковая задача обязана попадать к
одному исполнителю, а причина — печататься. Лишний вызов модели ради
выбора роли ещё и стоит денег на каждом запуске. Правила проверяются
тестами; модель проверить нечем.

**Не распознал — так и говорит.** «Тема не распознана, взят общий
набор» вместо случайного профиля. Одно слово «отчёт» не уводит в
делопроизводство задачу про редуктор: порог выше веса одиночного
слабого признака.

Долгая задача («в течение ночи», «автономно», «несколько часов»)
переводит в автономный режим сама.

Явное указание сильнее правил: `[профиль: cad] сделай отчёт`.
Ошиблись в имени — скажет об этом и разберёт задачу по правилам.

### Передача между агентами

В автономном режиме каждый пункт плана может уйти **своему** агенту:

```bash
python3 -m agent --auto --route "подготовь комплект по редуктору"
```

```
План:
  1. рассчитать зазоры и проверить STL
  2. подготовить отчёт в docx и таблицу замеров
  3. отправить комплект заказчику

── итерация 1 · #1 рассчитать зазоры и проверить STL
→ передано агенту «cad» (совпали признаки темы)
── итерация 2 · #2 подготовить отчёт в docx
→ передано агенту «office» (совпали признаки темы)
```

Общими остаются база, рабочая папка и пул MCP — меняются только навыки
и промпт. В простом режиме (`--do`) для долгих задач это включено само.

## Проверка модели: `--smoke`

```bash
python3 -m agent --smoke                    # модель из конфига
python3 -m agent --smoke -m qwen3-coder     # сравнить другую
python3 -m agent --smoke -v                 # с показом вызовов
```

Десяток задач по нарастающей, каждая с **численно проверяемым**
результатом: не «ответ выглядит разумно», а «в файле лежит 42».

Что ловится (всё это наблюдалось на живых моделях):

| дефект | как выглядит в жизни |
|---|---|
| не зовёт инструменты | «Сейчас я создам файл…» — и ничего не создаёт |
| текст в `reasoning_content` | `content` пуст, агент принимает намерение за результат |
| ломается на цепочке | один вызов делает, три подряд — теряет нить |
| не читает результат | инструмент вернул 42, модель отвечает «готово» |
| **выдумывает содержимое** | «файл содержит таблицу замеров» — файла нет |
| зацикливается | один и тот же вызов до упора в лимит шагов |

Вердикт — не проценты, а решение: **ГОДИТСЯ** / **ГОДИТСЯ С
ОГОВОРКАМИ** / **НЕ ТЯНЕТ**, с перечислением того, что именно сломалось.
Код возврата 0, 1 и 2 соответственно — удобно для скрипта.

```
ВЕРДИКТ: ГОДИТСЯ С ОГОВОРКАМИ
  · теряет нить на цепочке из трёх шагов — для автономного режима слаба
  · пустые ходы: 4 раза модель возвращала ответ без действия
  Годна для коротких задач под присмотром; для автономного прогона
  на часы — рискованно.
```

Работает во **временных папках**, ваши файлы не трогает. Тем же способом
сравнивают модели между собой: прогнать `--smoke -m A` и `-m B` и
посмотреть на вердикт и расход токенов — на ваших задачах, а не по
чужим бенчмаркам.

## Веб-интерфейс

```bash
python3 -m agent.server --port 8080          # только localhost
AGENT_API_TOKEN=... python3 -m agent.server --host 0.0.0.0
```

Одна страница без зависимостей, две вкладки.

**Работа** — чат с агентом. Перед запуском показывает, кто возьмёт
задачу («⤷ выбран профиль «office» — совпали признаки темы»); роль можно
заменить в выпадающем списке. Вызовы инструментов раскрываются.

**Вопрос агента приходит прямо в чат** карточкой с кнопками вариантов,
полем свободного ответа и кнопкой «Решай сам». Работает так: агент
останавливается и ждёт, ответ приходит отдельным запросом `POST /answer`
и будит его. Вопрос **переживает перезагрузку вкладки** — страница
подбирает висящие вопросы опросом `/questions` раз в три секунды.

Ждёт агент не вечно: 10 минут, дальше получает пустую строку и работает
по умолчанию, назвав допущение. Ответ на истёкший вопрос — честная
ошибка, а не молчаливое «принято».

**Прогоны** — история: состояние, время, шаги, токены, деньги. Внутри
прогона виден план с отметками (`[x]` сделано, `[!]` провалено,
`[?]` ждёт ответа) и журнал. Пункт можно закрыть, провалить или вернуть
в работу кнопками — правки идут прямо в базу.

### Эндпоинты

| метод | путь | зачем |
|---|---|---|
| GET | `/health` | жив ли сервис |
| GET | `/info` | конфигурация, инструменты, профили |
| POST | `/run` | задача → результат одним ответом |
| POST | `/run/stream` | то же, события построчно (NDJSON) |
| POST | `/dispatch` | кто возьмёт задачу и почему |
| GET | `/questions` | вопросы, ждущие ответа |
| POST | `/answer` | `{"id": 1, "text": "…"}` или `{"skip": true}` |
| GET | `/runs`, `/runs/N` | история прогонов |
| POST | `/plan` | сменить состояние пункта плана |

**Токен.** Наружу (`--host 0.0.0.0`) сервер не поднимется без
`AGENT_API_TOKEN` — откажется при старте. Токен только латиницей:
HTTP-заголовки не принимают кириллицу, и сервер скажет об этом сразу,
а не выдаст непонятную ошибку кодировки.

Сама страница отдаётся без токена — она пустая оболочка, все данные за
`Authorization`.

## Чего не хватает

Честно, по убыванию важности.

**1. Длинный прогон на живой модели.** Короткий путь проверен —
`--smoke` гоняет модель по десятку задач и выдаёт вердикт. А вот
восьмичасового автономного прогона на настоящем LLM не было: заглушки
не воспроизводят накопление контекста и усталость модели. Первый
длинный запуск — на неважной папке, с `-v` и `--max-usd`.

**2. Выбор исполнителя — простые правила.** Работает на понятных
формулировках, спотыкается на непрямых: «надо бы разобраться, почему
у нас всё встало» не даст `ops`. Лечится указанием `[профиль: ops]`
или доработкой правил в `agent/dispatch.py`.

**3. Передача между агентами односторонняя.** Пункт уходит исполнителю
и возвращается результатом. Агент не может сказать «это не ко мне,
отдайте в cad» — только провалить пункт. Настоящий обмен между
агентами не сделан намеренно: он даёт больше багов, чем пользы.

**4. Планировщик разбивает задачу один раз.** Перепланирование чинит
худший случай, но не делает план умнее.

**5. Параллельных вызовов инструментов нет.** Пять независимых чтений
файлов идут последовательно.

**6. Очереди прогонов нет.** Один прогон за раз; несколько задач —
несколько запусков вручную.

**7. В веб-морде нет автономного режима.** Есть чат, вопросы агента,
история прогонов и правка плана; запустить `--auto` из браузера нельзя —
только из CLI.

**8. PDF-парсер не читает сканы** (нужен OCR) и путает сложные колонки.
Создаваемый PDF — без картинок и колонтитулов.

**9. Windows не поддержан.** Предел памяти в `run_python` через
`resource`, пути и `bash -lc` — всё рассчитано на Linux.

**10. MAX требует юрлицо.** С августа 2025 боты публикуются только
через верифицированные организации РФ.
