# Быстрый старт MAOS (Multi-Agent Ontology System)

Этот документ поможет вам развернуть и протестировать MAOS за 30 секунд — без предварительной настройки базы данных и сторонних сервисов.

---

## 1. Мгновенный запуск за 30 секунд

Убедитесь, что у вас установлен Python 3.10+ и выполнен вход в репозиторий:

```bash
cd multi_agent_system_ontology
pip install -r requirements.txt
make quickstart
```

После выполнения команды в терминале появится сообщение:
```
[maos.quickstart] сервер запущен на http://127.0.0.1:8090/dashboard
```

Откройте в браузере страницу **http://127.0.0.1:8090/dashboard**. Вы сразу увидите готовый интерфейс системы с демо-агентами.

---

## 2. Что происходит под капотом `make quickstart`?

1. **Embedded PostgreSQL + pgvector (`pgserver`)**: приложение автоматически скачивает и поднимает изолированный локальный сервер PostgreSQL в папке `.maos_quickstart_pgdata/`. Вам не нужно устанавливать PostgreSQL в систему вручную.
2. **Инициализация схемы БД**: автоматически создаются таблицы агентов (`agent`), диалогов (`conversation`, `message`), векторной mid-term памяти (`memory_quantum`), а также долгосрочной онтологической памяти (`onto_entity`, `onto_relation`).
3. **Посев демо-агентов (`seed_demo_agents`)**:
   - `coder` — разработчик на Python/Golang (навыки: `files`, `site_qa` — проверка HTML-страниц);
   - `writer` — технический писатель и копирайтер (навыки: `web`);
   - `analyst` — аналитик данных и исследователь (навыки: `rag`, `vision` — анализ изображений и графиков).
4. **Запуск HTTP API / UI**: стартует сервер на порту 8090, обслуживающий REST API (`/v1/*`) и одностраничный веб-дашборд (`/dashboard`).

> **Совет:** если вы хотите запустить сервер без автоматического создания демо-агентов (с чистой базой), выполните:
> ```bash
> make quickstart --no-seed
> ```
> На пустой базе в дашборде отобразится приветственный баннер с кнопкой **«Создать демо-агентов»** (`POST /v1/onboarding/seed`).

---

## 3. Работа с Web-дашбордом

Дашборд MAOS состоит из 5 основных вкладок:

- **Overview** — общая статистика системы: количество агентов, диалогов, квантов памяти, сущностей онтологического графа и расход токенов.
- **Agents** — панель управления личностями агентов. Здесь можно редактировать slug, имя, описание (используемое семантическим роутером), системный промпт, набор навыков (`files`, `web`, `rag`, `office`, `site_qa`, `vision`) и привязку модели (`llm_ref`).
- **Chat** — интерфейс общения с агентами. Можно явно выбрать агента из выпадающего списка или выбрать **«(авто-роутинг)»** — в этом случае семантический роутер выберет агента по векторному сходству вашего вопроса с описаниями агентов.
- **Chain** — детерминированные цепочки выполнения (`Agent_A -> Agent_B`). Позволяет ставить составные задачи, где один агент генерирует решение, а второй проверяет или дорабатывает его.
- **Graph** — интерактивная визуализация долгосрочной памяти (онтологический граф сущностей `onto_entity` и связей `onto_relation`).

## 4. Проверка Graph-RAG и долгосрочной памяти в чате

MAOS использует **трёхуровневую память**:
1. **Short-Term** — история текущего диалога с экстренной суммаризацией при исчерпании контекстного окна.
2. **Mid-Term** — векторные кванты вопросов-ответов из прошлых диалогов.
3. **Long-Term (Multi-Hop Graph-RAG)** — онтологический граф сущностей и отношений с многошаговым обходом в глубину (до `long_term_max_hops` шагов, по умолчанию 2).

### Как проверить Multi-Hop Graph-RAG:
1. Во вкладке **Chat** напишите агенту определение или цепочку фактов:
   ```
   MAOS — это мультиагентная онтологическая система.
   starley создал MAOS.
   MAOS использует pgvector.
   ```
2. Запустите цикл фонового обслуживания, чтобы система извлекла знания из диалога:
   ```bash
   make maintenance
   ```
   *(Либо вызовите REST API: `curl -X POST http://127.0.0.1:8090/v1/maintenance/run`)*
3. Перейдите во вкладку **Graph** и нажмите **«Обновить граф»** — вы увидите узлы `project:MAOS`, `person:starley`, `project:pgvector` и связи `--[created]-->` и `--[uses]-->`.
4. Начните новый диалог и спросите:
   ```
   Какую технологию использует проект, созданный starley?
   ```
   Система выполнит 2-шаговый обход (`starley -> MAOS -> pgvector`), найдёт релевантный подграф в БД и подмешает в промпт системную заметку `[Релевантный подграф онтологии (Multi-Hop Graph-RAG, long-term memory):]`, чтобы агент дал точный ответ на основе всей цепочки фактов.

## 5. Фоновое обслуживание ("Deep Thinking")

Фоновый процесс MAOS выполняет 4 задачи по расписанию (по умолчанию раз в 5 минут, параметр `MAOS_MAINTENANCE_INTERVAL_SECONDS`):

- **Дистилляция (`distill`)**: диалоги длиннее `MAOS_MAINTENANCE_DISTILL_AFTER_MESSAGES` (по умолчанию 20 реплик) сворачиваются в компактную пару вопрос-ответ в таблице `memory_quantum`.
- **Дедупликация (`dedup`)**: пары квантов памяти с косинусным сходством выше `MAOS_MAINTENANCE_DEDUP_SIMILARITY` (0.97) очищаются от старых дублей.
- **Синтез графа (`synthesize_graph`)**: сущности одного типа (`kind`) с очень близкими описаниями сливаются в один узел (`merge_entities`).
- **Автоэкстракция сущностей (`extract_graph`)**: сканирование новых диалогов и автоматическое пополнение графа знаний новыми сущностями и связями.

Для ручного запуска одного цикла обслуживания используйте:
```bash
make maintenance
```

## 6. Переход в боевой режим (Production DB_DSN)

Для работы в production-окружении подключите MAOS к полноценному серверу PostgreSQL с установленным расширением `pgvector`:

1. Скопируйте шаблон переменных окружения:
   ```bash
   cp .env.example .env
   ```
2. Отредактируйте `.env` и укажите ваш `DB_DSN`:
   ```ini
   DB_DSN=postgresql://maos_user:strong_password@db-host:5432/maos_db
   ```
3. Запустите сервер:
   ```bash
   make serve
   ```
   Система автоматически применит схему БД при первом подключении.

## 7. Часто задаваемые вопросы (FAQ)

- **Как подключить локальную модель из LM Studio или Ollama?**  
  В файле `.env` укажите:
  ```ini
  LOCAL_BASE_URL=http://localhost:11434/v1
  DEFAULT_LOCAL_MODEL=local::llama3
  ```
  Для эмбеддингов через LM Studio:
  ```ini
  MAOS_EMBEDDING_PROVIDER=lmstudio
  MAOS_EMBEDDING_MODEL=text-embedding-nomic-embed-text-v1.5
  MAOS_EMBEDDING_BASE_URL=http://localhost:1234/v1
  ```
- **Как запустить все 446 тестов проекта?**  
  Выполните команду:
  ```bash
  make test
  ```
- **Как очистить временную БД быстрого старта?**  
  Выполните:
  ```bash
  make clean
  ```
