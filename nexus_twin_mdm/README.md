# NexusTwin MDM — AI-driven Holding MDM, Certification & Digital Twin

> Интеллектуальный сервис единой шины НСИ, управления мастер-данными, дедупликации и сертификации авиатехники (АП-25 / MoC) с архитектурой Цифрового Двойника (схема v5.7), автономным агентом **LangGraph** и полнофункциональным сервером **MCP (Model Context Protocol)**.

---

## 🌟 Название и философия сервиса: `NexusTwin MDM`

Название **`NexusTwin MDM`** отражает тройную суть платформы:
- **`Nexus` (Узел / Шина)** — единое связующее звено холдинга между разрозненными системами PLM (Teamcenter), ERP (1С/SAP) и AI Matcher, с контролем уровня доверия источников (`trust 0..100`) и автоматической дедупликацией.
- **`Twin` (Цифровой Двойник)** — консолидированное состояние объектов (`object_state`), семантические векторные эмбеддинги (`object_embeddings`, 1024 dim), конструкторские/производственные спецификации (`EBOM / MBOM` в `object_links`) и неизменяемая цепочка контрольных снимков (`baselines`) с криптографическим SHA-256 хешированием.
- **`MDM` (Master Data Management)** — управление нормативно-справочной информацией (НСИ): иерархии организационных единиц (`org_units` на `ltree`), онтология типов (`types` с JSON-схемами), классификатор единиц измерения (ОКЕИ / ISO в `uom`) и глобальный реестр уникальных кодов (`object_codes`).

## 🏗️ Архитектура системы и механизм дедупликации

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                             FastAPI (REST API + Web UI)                                │
├────────────────────────────────────────────────────────────────────────────────────────┤
│  LangGraph Autonomous Agent Graph:                                                     │
│  retrieve → reason → execute_tools → audit_data_quality → verify_compliance → finalize  │
├────────────────────────────────────────────────────────────────────────────────────────┤
│  MCP Server (Model Context Protocol):                                                  │
│  JSON-RPC 2.0 /api/mcp/rpc  |  SSE Discovery /api/mcp/sse  |  /api/mcp/tools           │
├────────────────────────────────────────────────────────────────────────────────────────┤
│  Слой нормализации и дедупликации (MDM v5.7 + DeduplicationEngine):                    │
│  Fuzzy-Match | LTree Org/Types | Time-Travel EAV | BOM Graph | SHA-256 Hash-Chain      │
├────────────────────────────────────────────────────────────────────────────────────────┤
│  PostgreSQL 14+ (vector, ltree, pgcrypto, pg_trgm, RLS)  │  SQLite Dev-Fallback        │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

### Ключевые возможности схемы v5.7 и движка дедупликации:
1. **Алгоритмическая дедупликация (`DeduplicationEngine`)**:
   - Автоматическое обнаружение кластеров дубликатов по нечеткому совпадению названий (SequenceMatcher / Levenshtein), схожести или префиксу мастер-кодов, пересечению внешних идентификаторов PLM/1С в таблице `object_xref` и ключевым атрибутам (`part_number`, `serial_number`, `model`).
   - **Транзакционное слияние (`merge_objects`)**: консолидация EAV-свойств на основе уровня доверия источника (`trust_based`, `primary_wins`, `duplicate_wins`), автоматическая перепривязка дочерних и родительских узлов EBOM/MBOM (`object_links`), soft-delete дубликата (`state = 'merged'`, `merged_into = primary_id`) и создание неизменяемого криптографического бейслайна SHA-256 о событии слияния (`DEDUPLICATION_MERGE`).
2. **Multi-tenant RLS (Row Level Security)**: безопасность на уровне строк на основе иерархии орг. единиц (`<@ current_user_org_path()`) и ролей (`viewer`, `editor`, `admin`) через переменные сессии (`app.current_user_id`, `app.role`).
3. **Time-Travel EAV-атрибуты**: таблица `object_properties` хранит историю каждого изменения со шкалой времени `valid_period`, уровнем доверия источника (`Source.trust`) и защитой от понижения доверия при перезаписи (`upsert_property`).
4. **Криптографический аудит бейслайнов**: таблица `baselines` реализует append-only цепочку снимков с вычислением SHA-256 (`snapshot_hash` → `prev_hash`) и автоматической функцией проверки целостности `verify_baseline_chain()`.
5. **Двойной режим работы (Postgres / SQLite Dev-mode)**: в продакшене сервис использует все расширения PostgreSQL 14+ (`ltree`, `vector`, `pgcrypto`, `uuid-ossp`, `pg_trgm`), а для разработки и тестирования автоматически переключается на SQLite с чистой Python-реализацией функций и триггеров.

## 🐳 Быстрое развёртывание (Docker Compose)

Проект полностью контейнеризован (мультистейдж-сборка, non-root пользователь, healthchecks):

```bash
# 1. Запуск в продакшен-режиме (PostgreSQL 16 + pgvector + NexusTwin App)
docker compose up -d --build
# Откройте http://localhost:8117

# 2. Остановка контейнеров
docker compose down

# 3. Легковесный dev-режим (Standalone SQLite без инфраструктуры БД)
docker compose -f docker-compose.dev.yml up -d --build
```

## 🔌 Сервер MCP (Model Context Protocol)

Сервис `NexusTwin MDM` может работать как удалённый **MCP-сервер** для Claude Desktop, LangChain, AWOS, Agent Toolkit или внешних мульти-агентных систем.

| Метод | Путь | Протокол |
|---|---|---|
| `GET` | `/api/mcp/tools` | Список инструментов с JSON-схемами для LLM |
| `POST` | `/api/mcp/rpc` | Стандартный JSON-RPC 2.0 (`tools/list` и `tools/call`) |
| `GET` | `/api/mcp/sse` | Discovery / SSE-протокол для подключения MCP-клиентов |

### Зарегистрированные инструменты агента и MCP:
1. `mdm.search_objects` — Поиск цифровых двойников в Холдинге по коду, названию или типу.
2. `mdm.get_bom_graph` — Извлечение конструкторской/производственной спецификации (EBOM/MBOM).
3. `mdm.verify_compliance` — Проверка SHA-256 цепочки бейслайнов и статуса сертификации АП-25.
4. `mdm.upsert_property` — Запись EAV-атрибута с проверкой уровня доверия источника.
5. `mdm.detect_duplicates` — Поиск и обнаружение потенциальных дубликатов в реестре МДМ.
6. `mdm.merge_duplicates` — Слияние дубликата в мастер-объект с консолидацией EAV-атрибутов.
7. `mdm.audit_data_quality` — Аудит качества нормативно-справочной информации и расчет индекса качества.
8. `mdm.get_org_hierarchy` — Чтение организационной структуры Холдинга.
9. `mdm.agent_query` — Вызов LangGraph-агента для сложного анализа соответствия и мастер-данных.

## 🧪 Автоматические тесты

Проект содержит **24 автоматических unit- и интеграционных теста**, проверяющих:
- Режим тестирования и LLM-синтез вымышленных предприятий (`test_synthesize_enterprise_endpoint`, `test_agent_synthesis_query`);
- Алгоритмический поиск дубликатов (`detect_duplicates`) и их транзакционное слияние (`merge_duplicates`) с проверкой сохранения целостности криптографической цепочки бейслайнов;
- CRUD НСИ-справочников и объектов;
- Контроль уровня доверия при записи EAV (`plm` 90% принимает, `ai` 30% отклоняет с HTTP 403);
- Вычисление и верификацию криптографических цепочек бейслайнов;
- Полный цикл и SSE-стриминг агента LangGraph (включая аудит дубликатов);
- Все JSON-RPC команды MCP-сервера;
- Все страницы веб-интерфейса.

Запуск тестов:

make test
# или: pytest -v tests/
