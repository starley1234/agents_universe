# Вопрос человеку, снимки, Python, бюджет, гигиена памяти

Пять добавлений. Каждое закрывает случай, который наблюдался в работе,
а не гипотетический. Зависимостей по-прежнему ноль: git берётся из
системы, всё остальное — стандартная библиотека.

```bash
python3 -m agent -P coder "почини тест"          # ask + vcs + python
python3 -m agent --auto --hours 6 --max-usd 2 "цель"
```

## 1. `ask_user` — спросить, а не угадать

Раньше агент на развилке ДОГАДЫВАЛСЯ. Догадка выглядит как работа и
всплывает через час, когда переделывать надо всё сделанное после.

| положение дел | что происходит |
|---|---|
| человек рядом (`run`, `chat`) | вопрос в терминал, ответ уходит модели и **записывается в память** |
| человека нет (`--auto`, сервер) | ответ **не выдумывается**: пункт плана помечается `blocked`, агент берёт следующий |

Заблокированный пункт **нельзя закрыть** через `plan_done` — инструмент
откажет. Прогон с незакрытым вопросом завершается со статусом `blocked`,
а не `done`, и вопросы печатаются в итоге:

```
Прогон #7: blocked
План: 4 из 6 пунктов, заблокировано вопросом: 1

ЖДУТ ОТВЕТА ЧЕЛОВЕКА:
  #12 выбрать материал корпуса
     ВОПРОС: сталь 40Х или алюминий Д16Т?
```

**Лимит — 3 вопроса на запуск.** Дальше инструмент отвечает отказом и
требует работать по разумному умолчанию, назвав допущение вслух. Иначе
модель заменяет работу анкетой.

Ответ можно дать цифрой, если предложены варианты.

## 2. `vcs` — снимки и откат

Первый прогон на рабочей папке страшно запускать ровно потому, что
откатить нечего. Теперь есть.

| инструмент | что делает |
|---|---|
| `snapshot` | сохранить состояние папки |
| `changes` | что изменилось после снимка: файлы и различия |
| `snapshots` | список снимков: хеш, время, описание |
| `revert` | вернуть папку к снимку |

**Снимок перед каждым шагом делается автоматически** (`vcs_auto`, по
умолчанию включено). Первый снимок фиксирует исходное состояние — то,
что было до агента.

Три решения, каждое из-за пойманного тестом дефекта:

- **репозиторий отдельный**, в `.agent-git`. Ваш собственный `.git`,
  его история и индекс не трогаются;
- **`read-tree --reset`, а не `checkout`** — checkout восстанавливает
  файлы из снимка, но не убирает появившиеся после; мусор оставался;
- **«нечего фиксировать» определяется сравнением индекса**, а не
  разбором текста git: формулировки зависят от версии и языка системы.

Откат **обратим**: состояние до отката тоже сохраняется снимком, и его
хеш называется прямо в ответе. Несохранённая работа при откате не
теряется.

```
Папка возвращена к снимку a1b2c3d. Состояние до отката сохранено
в снимке e4f5g6h — передумаешь, вызови revert с to=e4f5g6h.
```

## 3. `python` — счёт без Docker

Жалоба, повторявшаяся дважды: `run_command` не работает без
демона Docker. А считать надо всегда, и это не опасная операция.

| инструмент | что делает |
|---|---|
| `run_python` | выполнить код, вернуть напечатанное |
| `run_script` | запустить файл `.py` как `__main__` |

Работает при **любом** режиме песочницы, подтверждения не требует.

- отдельный процесс — зависание или падение не трогают агента;
- тайм-аут (60 с) и обрезка вывода;
- **предел памяти 512 МБ** через `resource` — на сервере с 1 ГБ важно;
- **номера строк в traceback настоящие**: код компилируется отдельно,
  а не приписывается к прологу, иначе модель ищет ошибку не там.

**Границы честно:** изоляции сети и файловой системы здесь нет. Это
инструмент удобства, а не песочница. Для недоверенного кода остаётся
`run_command` с `sandbox.mode=docker`.

## 4. Бюджет денег

```bash
python3 -m agent --auto --hours 8 --max-usd 5 "цель"
```

Проверка **между итерациями**: прервать оплаченный запрос нельзя, а
остановиться на пороге можно. `0` (умолчание) — без предела: на
локальной модели платить не за что.

Итог называет причину и способ продолжить:

```
ОСТАНОВЛЕН ПО БЮДЖЕТУ: потрачено $5.0210 при пределе $5.00.
План не доделан — продолжить можно командой --resume 7 с большим --max-usd.
```

## 5. Гигиена памяти: `revise` и `forget`

Память, которая только копится, со временем начинает врать: старое
решение лежит рядом с новым, и `recall` выдаёт оба.

| инструмент | что делает |
|---|---|
| `revise` | исправить факт по номеру `#N` |
| `forget` | удалить факт по номеру либо всё найденное по запросу |

`recall` теперь показывает номера — без них править нечего.

Индекс поиска обновляется вместе с текстом (триггер `fact_au`). Без
него поиск шёл по устаревшему индексу: исправленный факт находился по
СТАРЫМ словам и не находился по новым.

**Стереть всю память разом нельзя.** Пустой запрос в `forget` —
ошибка, а не «удалить всё». Одна такая оговорка стоила бы всей истории
работы.
