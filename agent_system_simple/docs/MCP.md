# Внешние сервисы через MCP

Веб-поиск, загрузка страниц, генерация картинок и речи **не написаны в
нашем коде**. Они подключаются как MCP-серверы — те же, что вы уже
используете в LM Studio. Наша задача — говорить на их протоколе.

## Настройка

```json
"skills": ["files", "shell", "memory", "present", "mcp"],
"mcp": {
  "servers": {
    "search": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-brave-search"],
      "env": { "BRAVE_API_KEY": "ключ" },
      "rate_limit": 20
    },
    "fetch": {
      "command": "uvx",
      "args": ["mcp-server-fetch"],
      "rate_limit": 0
    },
    "remote": {
      "transport": "http",
      "url": "http://127.0.0.1:3000/mcp",
      "headers": { "Authorization": "Bearer токен" }
    }
  }
}
```

| поле | смысл |
|---|---|
| `rate_limit` | минимум секунд между вызовами. **0 = без лимита** |
| `transport` | `stdio` (подпроцесс, как в LM Studio) или `http` |
| `enabled` | `false` — временно отключить, не удаляя настройку |
| `only_tools` | взять с сервера лишь часть инструментов |

Готовый пример со всеми полями — `examples/config.mcp.json`.

## Лимиты — ровно как вы просили

Поиск обычно платный и квотируемый, загрузка страниц — бесплатная:

```json
"search": { "rate_limit": 20 },   // не чаще раза в 20 секунд
"fetch":  { "rate_limit": 0 }     // безлимитно
```

Лимит соблюдается **на стороне клиента**: если модель дёрнет поиск
дважды подряд, второй вызов подождёт. Модель об этом предупреждена —
лимит дописывается в описание инструмента, и в ответе появляется
пометка `[ожидание лимита 20 с]`.

## Устойчивость

**Недоступный сервер не ломает агента.** Не поднялся, не ответил, отдал
мусор — отключается, причина в лог, остальное работает. Проверено:
битый сервер в пуле не мешает рабочему.

Имена префиксуются сервером: `search_search`, `fetch_fetch`. Два сервера
с инструментом `search` не столкнутся.

В автономном режиме пул поднимается **один раз** на весь прогон, а не на
каждой итерации.

## Проверка

```bash
python3 -m agent --check -c examples/config.mcp.json
```

Покажет по каждому серверу: подключён, сколько инструментов, какой лимит
— или почему недоступен.

## Что проверено

Тесты работают с **настоящим** MCP-сервером (подпроцесс и HTTP), а не с
заглушками внутри Python.

| проверка | результат |
|---|---|
| рукопожатие, tools/list, tools/call по stdio | да |
| то же по HTTP | да |
| лимит 1 с на 3 вызовах | выдержан |
| без лимита — быстро | да, разница кратная |
| битый сервер не мешает рабочему | да |
| выключенный пропускается | да |
| ошибка сервера приходит как ToolError | да |
| обе формы записи конфига | да |

Диверсии: отключение лимита — 2 падения; падение пула на битом
сервере — трейсбек. Тесты ловят.
