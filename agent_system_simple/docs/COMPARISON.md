## 2. Что каждое решение делает лучше

### Наша система сильнее в

- **автономии** — сутки работы, память, онтология, возобновление;
- **приватности** — данные и модель у вас;
- **предсказуемости** — 137 тестов, проверенных на чувствительность;
- **стоимости** — локальная модель, токены бесплатны;
- **лаконичности** — 2810 строк без зависимостей.

### Arena сильнее в

- **мультимодальности** — картинки, речь, поиск, загрузка страниц;
- **подаче результата** — просмотрщик артефактов, богатые превью;
- **зрелости интерфейса**;
- **готовности к работе** — ничего не разворачивать.

### Честно о слабых местах нашей системы

Три пробела прямо бьют по «вау-эффекту»:

1. **Нет выхода в интернет.** Агент не может проверить факт, найти
   аналог, посмотреть цены. Для маркетинга это блокер.
2. **Нет генерации медиа.** Лендинг без визуала — половина продукта.
3. **Нет показа артефакта.** Результат лежит файлом, человек должен сам
   его искать. «Вау» рождается в момент показа.

Плюс инженерные пробелы: нет повтора при сбое сети (одна ошибка рвёт
восьмичасовой прогон), нет перепланирования, нет уточняющих вопросов.

## 3. Что рекомендую строить

**База — наша система.** Она проверена, автономна, приватна и лаконична.
Переписывать нечего. Нужно закрыть три пробела, которые и дают «вау».

### Приоритет 1 — без этого «вау» не будет (~350 строк)

| навык | что даёт | объём |
|---|---|---|
| `web` — поиск + загрузка страниц | агент проверяет факты, находит аналоги, собирает данные | ~120 строк на `urllib` |
| `media` — генерация картинок через API | лендинги, схемы, иллюстрации | ~80 строк |
| `present` — показ артефакта | HTML-отчёт со сборкой результатов прогона | ~150 строк |

`present` — самое недооценённое. После 8 часов автономной работы агент
должен выдать **одну страницу**: что сделано, какие числа получены,
какие файлы созданы, что не получилось. Это и есть эффект.

### Приоритет 2 — надёжность длинных прогонов (~200 строк)

| что | зачем |
|---|---|
| повтор при сбое сети (3 попытки) | одна ошибка сети не рвёт 8-часовой прогон |
| учёт токенов и денег | провайдеры возвращают `usage`, мы его игнорируем |
| перепланирование | если план оказался плохим, агент его переделает |
| `ask_user` в неавтономном режиме | уточнить вместо угадывания |

### Приоритет 3 — масштаб (~250 строк)

| что | зачем |
|---|---|
| параллельные вызовы инструментов | 3 независимых чтения за один шаг вместо трёх |
| маршрутизация моделей | дешёвая на рутину, сильная на сложное |
| очередь прогонов | несколько задач подряд без человека |

**Итого ~800 строк** поверх существующих 2810. Останется лаконично.

## 4. Гибридная схема — то, что советую на практике

Не «или/или», а разделение по роли:

```
GPU-сервер (Devstral 22B)     ←  рутина, автономные прогоны, приватное
        │                        токены бесплатны, работает сутками
        │
   наша система  ──────────→  OpenRouter (сильная модель)
   (оркестратор)                ←  сложное рассуждение, финальная сборка
        │                          платим только за то, что важно
        ↓
   Arena.ai  ←  разовые задачи, где нужны медиа и быстрый результат
```

Правило переключения простое: **всё, что делается локально — делается
локально**. Наружу уходит только то, где качество решает.

Экономия на этом больше, чем от всех технических мер: сутки автономной
работы на локальной модели стоят электричества, на облачной — заметных
денег.

## 5. Ответ на исходный вопрос

**Универсальный и масштабируемый инструмент** = наша система
+ три навыка первого приоритета.

Почему именно она базой, а не Arena или готовый фреймворк:

| критерий | обоснование |
|---|---|
| **масштабируемость** | новый домен = модуль `build(ws)` + JSON-профиль. Проверено на двух крайних: CAD и маркетинг |
| **универсальность** | 9 провайдеров, 6 ролей, онтология не зашита в код |
| **автономность** | сутки без человека — у SaaS-решений этого обычно нет |
| **лаконичность** | 2810 строк, ноль зависимостей. Ваш принцип соблюдён |
| **проверяемость** | 137 тестов, каждый проверен на способность падать |

Чего **не** советую добавлять: рой агентов (умножает стоимость, губит
отладку), векторную базу (`search_text` + FTS5 честнее), тяжёлый
фреймворк (на 1 ГБ — проигрыш).
