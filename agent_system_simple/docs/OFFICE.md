# Документы и связь с внешним миром

Два навыка: `makedocs` создаёт Word, Excel, PowerPoint и PDF; `comms`
работает с почтой, Telegram и MAX.

```bash
python3 -m agent -P office "собери отчёт по замерам и отправь начальнику"
```

Обязательных зависимостей по-прежнему ноль. `python-docx`, `openpyxl`,
`python-pptx` используются, если есть, — качество выше. Нет — работает
запасной путь на стандартной библиотеке, потому что docx/xlsx/pptx это
ZIP с XML внутри. Проверено тестом: файлы, собранные без библиотек,
читаются настоящими библиотеками корректно.

---

## 1. Создание документов (`makedocs`)

**Один вход на все форматы — Markdown.** Заставлять модель помнить
четыре разных набора вызовов значит получить четыре набора ошибок.

| разметка | во что превращается |
|---|---|
| `# Заголовок` | заголовок, в презентации — новый слайд |
| обычный текст | абзац / пункт слайда |
| `- пункт` | список |
| `\| а \| б \|` | таблица, в Excel — лист |
| `---` | разрыв страницы или слайда |

| инструмент | что делает |
|---|---|
| `make_docx` | письма, отчёты, записки |
| `make_xlsx` | таблицы и реестры; **числа записываются числами** |
| `make_pptx` | доклады; слайд = заголовок + пункты или таблица |
| `make_pdf` | то, что уходит наружу и не должно правиться |

### Три решения, каждое из-за конкретной проблемы

**Числа в Excel — числами, а не текстом.** `0.48` в ячейке-строке не
суммируется, и таблица выглядит рабочей, пока кто-то не попробует
посчитать итог. Распознаются целые, дробные и запятая как разделитель.

**Имя листа берётся из заголовка над таблицей.** Excel не принимает
`: \ / ? * [ ]` и длину больше 31 символа — символы заменяются,
имя обрезается, повторы получают суффикс.

**PDF со встроенным шрифтом.** Без встраивания кириллица в PDF
превращается в пустые квадраты. Шрифт TrueType (DejaVu или Liberation)
кладётся внутрь файла вместе с картой `ToUnicode` — без неё текст
нельзя ни найти поиском, ни скопировать. Проверено сторонней
библиотекой: `pypdf` извлекает «Отчёт о приёмке», а не «δϕύϦϑϏυ».

Шрифта в системе нет — `make_pdf` честно откажет и предложит docx,
вместо того чтобы выдать файл с квадратами.

## 2. Связь с внешним миром (`comms`)

Отправка наружу — **единственное необратимое действие агента**. Файл
можно вернуть снимком, письмо нельзя. Поэтому защита строже.

| инструмент | что делает |
|---|---|
| `send_email` | письмо с вложениями (SMTP) |
| `list_email` | последние письма: дата, отправитель, тема; поиск по слову |
| `read_email` | письмо целиком, вложения в рабочую папку |
| `send_telegram` | сообщение в Telegram |
| `send_max` | сообщение в MAX |
| `comms_status` | что настроено и кому разрешено писать |

### Белый список

```json
"comms": {
  "allow_to": ["*@firma.ru", "boss@partner.com"]
}
```

- **Пустой список означает «никому», а не «всем».** Умолчание обязано
  быть безопасным.
- Адреса нет в списке — письмо **не уходит**, а сохраняется черновиком
  в `outbox/`, и агент получает прямой ответ:

```
НЕ ОТПРАВЛЕНО. Получателя 'chuzhoy@evil.ru' нет в белом списке
(*@firma.ru, boss@partner.com).
Черновик сохранён: outbox/001-email-chuzhoy@evil.ru.txt — человек
прочитает и отправит сам. Не считай это выполненной отправкой.
```

Последняя фраза не для красоты: без неё модель отчитывается «письмо
отправлено» и закрывает задачу.

- Маска `*@firma.ru` разрешает домен целиком, но **не** подделку
  `kto@firma.ru.evil.com` — проверяется окончанием, а не вхождением.

### Пароли и токены — только из окружения

В конфиге их нет, он кладётся в git.

```bash
export AGENT_SMTP_PASS=...      # пароль почты
export AGENT_IMAP_PASS=...      # если отличается от SMTP
export AGENT_TG_TOKEN=...       # Telegram
export AGENT_MAX_TOKEN=...      # MAX
```

### Особенности MAX

API отличается от Telegram, и различия существенные:

- домен **`platform-api2.max.ru`** (не `botapi.max.ru`);
- токен **только в заголовке** `Authorization` — передача в
  query-параметрах больше не поддерживается;
- `chat_id` в query, текст в теле запроса;
- предел текста **4000 знаков**, у Telegram 4096.

Длинные сообщения режутся по границе строки, а не посреди слова.

### Чтение почты

`list_email` и `read_email` белым списком не ограничены: читать
безопасно. Вложения сохраняются по явной просьбе, **исполняемые файлы
не сохраняются никогда** (`.exe`, `.js`, `.msi`, `.ps1` и подобные) —
вместо файла в ответе строка «НЕ СОХРАНЁН (исполняемый)».

## Профиль `office`

```bash
python3 -m agent -P office "сделай отчёт по замерам в docx и xlsx"
```

Навыки: `files, documents, makedocs, comms, memory, present` —
32 инструмента. Читает входящие документы, создаёт новые, рассылает.

Пример конфига: `examples/config.office.json`.

## Тесты

```bash
python3 tests/test_office.py     # 81 проверка
```

Два правила, без которых тесты были бы обманом:

1. **Файл проверяется чтением обратно**, а не фактом создания. Пустой
   ZIP тоже «существует».
2. **Отправка проверяется на настоящем SMTP-сервере** в том же
   процессе: письмо реально уходит по сокету, содержимое сверяется.

Диверсии — код ломался намеренно, тест обязан был упасть:

| что ломали | что упало |
|---|---|
| пустой белый список означает «всем» | 2 проверки |
| маска домена ловит `partner.com.evil.ru` | 1 |
| черновик молча ничего не делает | 7 |
| отказ оператора игнорируется | 2 |
| вложение не прикладывается | 1 |
| числа в xlsx пишутся текстом | 1 |
| PDF без карты `ToUnicode` | 4 (кириллица стала «δϕύϦϑϏυ») |

## Границы честно

- **Вёрстка простая.** Колонтитулы, нумерация страниц, стили фирменного
  бланка не поддержаны. Нужен бланк — берите шаблон и правьте
  `python-docx` напрямую.
- **PDF без картинок и без переносов.** Таблица в PDF выводится
  строками через `|`, а не сеткой.
- **HTML-письма** приводятся к тексту грубо, вёрстка теряется.
- **MAX требует юрлицо.** С августа 2025 боты публикуются только через
  верифицированные организации РФ; физлицам и самозанятым доступа нет.
